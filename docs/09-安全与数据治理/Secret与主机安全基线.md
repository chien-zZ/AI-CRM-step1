# Secret 与主机安全基线

- 状态：已批准
- 架构依据：ADR-0021、ADR-0022、ADR-0023

## 核心规则

- Secret 只存在于批准的生成端、目标主机受限文件和加密离线应急包。
- 代码、文档、Git、Compose 字面值、镜像、数据库、业务配置、日志、Sentry 和前端制品只保存引用，不保存 Secret 值。
- 每个环境、服务和用途使用独立凭据；容器只读挂载自身需要的单个 Secret。
- Secret 缺失或错误时失败关闭，不回退默认值。
- 文件式方案不具备读取审计和自动租约，必须用最小权限、SSH/sudo/文件变更审计、轮换和应急演练补偿。

## 主机文件要求

- 生产 Secret 根目录由 root 拥有，目录不可被普通用户遍历。
- 文件默认 `0400`，只有明确需要时使用受控组 `0440`。
- 使用临时受限文件和原子替换，禁止在终端回显或 Shell 历史中出现值。
- 不挂载整个 Secret 目录，不将 Secret 复制到容器可写层或共享 Volume。
- 删除旧版本前确认新版本已生效、依赖已切换并保留批准的回滚或应急方式。

## 运维访问要求

- SSH 使用个人密钥，禁止密码登录、远程 root 直登和日常共享账号。
- sudo、Secret 文件变化、登录失败、云权限和备份应急包操作进入安全审计。
- 状态服务与管理端口只走私网和最小安全组，不向公网暴露。
- 离职、设备丢失或权限变化立即回收访问，并评估相关凭据轮换。

## 数据与备份

- 生产数据不进入开发人员电脑；测试使用合成或批准的脱敏数据。
- 普通备份不包含明文 Secret 根目录。
- 最小灾难恢复 Secret 使用 `age` 离线公钥加密，解密私钥与生产主机和 COS 分离。
- 主机磁盘、COS 和备份启用可用的静态加密；网络传输使用 TLS/SSH。
- 字段级加密、展示脱敏、导出审批和留存删除等待正式数据分类，不从历史 CRM 字段推断。

## 安全事件

- 发现 Secret 进入 Git、日志、Sentry、聊天或工单时，不能只删除文本；应视为可能泄露并轮换。
- 先限制继续访问和传播，再撤销/轮换凭据、会话、Token 或证书，最后清理副本并补充检测。
- 事件记录只引用 Secret 名称和版本，不复制值。
- 主机 root、部署账号或离线私钥疑似失陷时，按其可访问范围扩大轮换和恢复评估。

## 上线检查

- Secret 清单、Owner、消费者和轮换 Runbook 完整。
- Compose 只有 Secret 引用，容器挂载只读且最小。
- 仓库扫描、配置失败测试、权限测试和轮换演练通过。
- 备份应急包能够在隔离环境解密和恢复，且测试产物已安全清理。
- 日志与 Sentry 抽样没有 Secret、Token、Cookie 或个人数据。
