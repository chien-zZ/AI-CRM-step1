# 可观测性与告警基线

- 状态：公共字段 API 已实现并测试；应用接入、账号和阈值待后续任务评审
- 适用范围：所有应用、客户端、后台任务、运行组件和部署环境
- 架构依据：ADR-0022

## 开发要求

- 通过 `packages/observability` 公共入口创建 Logger、Trace 和 Error Reporter，不在领域模块直接初始化 Pino、Sentry 或云厂商 SDK。
- 使用路由模板、操作名、稳定错误码和内部引用；不记录请求正文、完整 URL、数据库行或消息完整载荷。
- 错误保留原始 Cause 链供服务端安全序列化，但公开响应只返回稳定错误码和 Trace 引用。
- HTTP、事件、Job、Workflow、文件与第三方调用保持 Trace/Correlation Context；上下文丢失不得影响业务正确性。
- 新增日志字段、Sentry Context/Tag、Metric Label 前检查敏感性和基数。

公共实现位于 `packages/observability`。应用通过项目自有 `ApplicationLogger`、`ErrorReporter`、`TraceContext` 和健康结果类型接入，不向模块公开 Pino、Sentry 或 OpenTelemetry SDK 类型。日志操作名、错误码和关联 ID 使用有界稳定格式；任意自由文本只能先由拥有模块归类为受控枚举或摘要，不能直接记录。

## 必测清洗项

- Authorization、Cookie、Set-Cookie、Token、Session、验证码和 Secret。
- 手机号、身份证号、邮箱、地址、客户沟通、表单正文和附件内容。
- SQL 参数、Webhook、供应商请求/响应和消息载荷。
- 前端 URL Query、浏览器存储、控制台对象、Source Map 上传凭据。

清洗测试必须覆盖嵌套对象、数组、Cause、循环引用、大小限制和未知字段。未知对象默认只输出类型与安全摘要。

## 健康检查规则

- Liveness 只表示进程是否需要重启，不把普通下游故障当成进程死亡。
- Readiness 表示实例能否安全承接当前职责，并定义依赖降级行为。
- Deep diagnostics 只用于受控运维访问，不能暴露连接、版本漏洞和内部拓扑。
- Uptime 探测位于两台生产服务器之外，检查最小公开入口和批准关键路径。

## 告警上线门禁

- 告警包含环境、服务、严重级别、症状、开始时间和 Runbook。
- 告警有唯一 Owner、升级人和确认/关闭方式。
- 瞬时错误使用连续窗口、去重、聚合或静默，避免每次异常直接通知。
- 发布前用受控故障验证触发和恢复通知，不能只检查规则已保存。
- 无法行动的低价值信号保留为日志或看板，不升级为呼叫告警。

## 发布检查

- Sentry Release 与不可变镜像/前端制品版本一致。
- Production Environment、采样和数据清洗配置显式生效。
- Source Map 已上传到正确 Release，上传 Token 未进入制品。
- Pino 输出有效单行 JSON，Docker 轮转与磁盘限制已生效。
- Trace 能从入口贯穿至少一个 Outbox/RabbitMQ/Worker walking skeleton。
- Sentry/云监控不可用不会阻断业务或导致无限内存队列。

## 事故处理

- 先以告警时间、环境、服务、Release、Trace/Correlation ID 缩小范围。
- Sentry 和日志仅用于技术诊断；涉及业务动作与责任追溯时查询正式审计记录。
- 发现敏感数据进入观测系统时立即停止继续发送、限制访问、记录安全事件并按保留/删除能力处置。
- 修复后补充脱敏回归测试、告警规则或 Runbook，避免只人工清理单次事件。
