# 部署与发布基线

- 状态：架构方向已确认，具体拓扑和版本待实施评审
- 适用范围：`deploy/`、CI/CD、两台生产服务器、预发布和生产发布
- 架构依据：ADR-0002、ADR-0003、ADR-0011、ADR-0021

## 部署原则

- 两台服务器分别运行自己的 Docker Compose Project；部署工具必须明确目标主机，禁止假设 Compose 跨主机调度。
- 应用与第三方镜像必须固定版本；生产发布记录镜像摘要、契约版本、迁移版本、配置版本和操作人。
- 环境配置启动时进行类型和完整性校验。生产 Secret 使用 ADR-0023 的受限文件、Compose Secret 和 `*_FILE` 引用，不写入仓库、镜像、Compose 字面值或生产 `.env`。
- 状态目录、临时目录、日志、备份目录和只读配置挂载必须显式区分，并设置容量与权限。
- 每个服务声明存活、就绪、优雅停止、资源限制、日志轮转和依赖不可用行为。

## 发布门禁

生产发布前至少确认：

- `pnpm check`、契约检查、迁移检查和适用的集成/E2E 测试通过。
- 使用与预发布验证相同摘要的不可变镜像。
- 新旧 API、事件、Job 和数据库结构在发布窗口内兼容。
- PostgreSQL 恢复点可用，破坏性变更有前滚修复和人工批准。
- Keycloak Realm、Flowable、Nginx、RabbitMQ 拓扑和运行配置变更已版本化并在预发布验证。
- Secret 清单、文件权限、最小挂载、轮换顺序和旧凭据撤销步骤已验证，发布记录不包含 Secret 值。
- 逐台更新 API 副本；每台通过健康与关键路径冒烟后才能继续。
- Worker 已处理在途任务、停止接收和新旧 Handler 共存风险。
- 回滚镜像、触发条件、负责人和通信方式明确。

## 备份与恢复门禁

- PostgreSQL 备份和 WAL 不只保存在生产服务器本地。
- 应用、Keycloak 和 Flowable 数据分别列出恢复顺序和依赖。
- Redis 和 RabbitMQ 分别说明哪些数据可重建、哪些需要持久化以及丢失后的业务影响。
- Compose、Nginx、Realm、流程引擎和消息拓扑配置能够从仓库受控版本重建。
- 恢复演练从空主机或等价隔离环境开始，并记录实际恢复点、耗时、数据差异和改进项。

## 禁止事项

- 禁止生产使用 `latest`、浮动大版本或未评审镜像。
- 禁止用 `docker compose down -v`、删除宿主目录或重建 Volume 作为常规发布步骤。
- 禁止把数据库迁移回滚等同于应用镜像回滚。
- 禁止在两台服务器上宣称三节点仲裁能力或自动高可用。
- 禁止预发布连接生产数据库、RabbitMQ、Redis、Keycloak Client、COS Bucket 或供应商账号。

## 实施前待补

- 两台服务器和各服务的最终放置矩阵。
- 固定镜像、端口、Volume、网络、资源和健康检查清单。
- CI/CD 身份、镜像仓库、部署权限与人工批准流程。
- RPO、RTO、备份保留和恢复演练 Runbook。
- Nginx 入口故障时的 DNS/IP 人工切换步骤。
