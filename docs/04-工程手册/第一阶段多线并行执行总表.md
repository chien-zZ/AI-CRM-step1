## 1. 用途与边界

本表只记录工作包状态、所有权、Review 闭环、共享资源租约、合并门和验收证据，不承载永久业务规则，也不替代根 `AGENTS.md`、ADR、契约、模块说明、实施计划或验收清单。

已知事实：

- G1 已完成。
- `IAM-01`～`IAM-03`、`ASY-01`、`PRC-01` 已通过 G2。
- `CMP-01` 仍受剩余模块 G2 前置依赖阻塞。
- `CLI-01` 已完成业务中立化整改、独立代码与四视口视觉 Review，并串行合并。
- 当前没有远程仓库或服务端主分支保护。

允许的假设：

- 使用合成人员、组织、权限、任务、通知、表单、文件、流程和故障 Fixture 验证平台能力。
- 四个 Agent 仅在互相隔离的本地 Git Worktree 中并行写入。
- `main` 由 Integration Owner 串行更新，本地流程控制暂时代替尚不存在的远程保护。

禁止的假设：

- 不从 Demo、访谈或历史材料推断 CRM 实体、字段、状态、角色、SLA、审批路线或指标。
- 不把本地 Worktree 隔离描述为远程主分支保护或完整 G0 技术门禁。
- 不允许多个 Owner 同时修改根 Lockfile、生成制品、全局迁移编号或 Composition Root。

非目标：

- 本表不新增 CRM 领域模块、真实 Provider、真实 AI 用途或生产 Secret。
- 本表不承诺日历排期、人员工时、SLA、RPO、RTO 或自动故障切换。

## 2. 状态机与完成规则

工作包使用以下状态：

```text
BACKLOG -> READY -> IMPLEMENTING -> SELF_REVIEW -> INDEPENDENT_REVIEW
  -> FIXING -> RE_REVIEW -> G2_ACCEPTED -> MERGED
```

任何阶段均可进入 `BLOCKED`。只有专项测试、完整 `pnpm check` 和独立 Review 均通过，且所有可执行 P0/P1/P2/P3 finding 清零、未决架构或契约问题清零，才可进入 `G2_ACCEPTED`。Review 结论必须写入任务 handoff，不能只写 `LGTM`。

- Owner 自审结果和专项测试证据。

- 原 Reviewer 的复审结论；若发现新问题则继续 `FIXING -> RE_REVIEW`。
- 最终 `pnpm check` 结果、迁移/契约/客户端专项证据和合并提交。
