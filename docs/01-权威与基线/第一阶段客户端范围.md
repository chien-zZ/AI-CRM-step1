# 第一阶段客户端范围

- 状态：已批准
- 日期：2026-07-22
- 架构依据：ADR-0003、ADR-0015、ADR-0016、ADR-0017、ADR-0018、ADR-0019

## 正式应用入口

第一阶段必须创建并纳入构建、测试和部署范围：

- `apps/workbench-web`：内部 PC 工作台。
- `apps/internal-mobile`：内部移动端。
- `apps/external-portal`：外部端。

三个应用先建设业务中立壳层和 walking skeleton。具体 CRM 页面、内部移动载体、外部用户类型及业务流程必须等待独立确认。

## 隔离原则

- 三个应用独立构建和发布，内部与外部端不能通过隐藏菜单共用同一个发布物。
- 外部端使用独立认证客户端和最小 API 暴露面，不加载内部导航与管理能力。
- 外部操作显式选择匿名、邀请或长期登录模式；邀请只表达限定能力，不表达人员身份。
- 共享只发生在正式契约、生成客户端、设计 Token 和已经证明复用的组件中。
- 端内校验和隐藏不能替代服务端授权、领域校验和幂等。

## 已确认端形态

- `internal-mobile`：Taro + React + TypeScript + NutUI React，输出 H5，运行于企微工作台 WebView 和普通手机浏览器。
- `external-portal`：Taro + React + TypeScript + NutUI React，从一个独立应用源码输出 H5 与微信小程序。
- 两个 Taro 应用独立，不创建原生 iOS/Android App，不采用 Expo、React Native 或 JPush。
- 移动端依赖版本按 Taro/NutUI 兼容矩阵锁定，不强制使用 PC Web 的 React 19。

## 当前仍待确认

- 首个外部业务场景及主体；如果需要长期登录，再确认首次关联与账号恢复。内部 Keycloak 账号恢复、通知呈现、发布账号和审核方式仍待确认。
- 锁定依赖版本、移动设计 Token、路由、错误、弱网和文件上传规范。
- 企微工作台配置、微信小程序账号、域名、隐私和审核材料。

认证传输和服务端会话已由 ADR-0017 确认，外部访问分级由 ADR-0019 确认。不得将这些技术边界理解为第三方登录、匿名业务端点、邀请流程、具体业务页面或外部身份模型已经确认。
