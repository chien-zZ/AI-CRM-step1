# ADR-0024：AI 网关与 AI 治理边界

- 状态：已接受
- 日期：2026-07-23
- 决策人：项目负责人
- 适用范围：`packages/platform-modules/ai-gateway`、`contracts/ai`、`platform-sdk`、AI Provider Adapter 与未来 AI 用途
- 依赖决策：ADR-0003、ADR-0007、ADR-0010、ADR-0011、ADR-0013、ADR-0020、ADR-0022、ADR-0023

## 已知事实

- 项目负责人确认采用调整后的历史 AI 网关方案：统一代理、模型可切换、输入治理、调用记录、Prompt 版本、成本控制、人工确认和供应商隔离。
- 当前没有已确认的产品 AI 用途、供应商、模型、账号、预算、数据分类、Prompt、验收 Owner 或生产合规结论。
- 历史材料中的“跟进摘要”“客资评级建议”等属于未确认 CRM 业务，不能直接成为第一阶段契约或实现。
- 项目已建立 `integration-runtime`、RabbitMQ/Redis/Outbox、文件式 Secret、轻量可观测和业务中立平台 SDK 边界。
- “全 AI 开发”描述开发方式，不代表运行时产品可以自动访问仓库、数据库、生产数据或执行领域动作。

## 允许的假设

- 多个未来 AI 用途需要复用模型路由、调用治理、结构化输出校验、成本记录和供应商 Adapter。
- 大多数生成任务可以异步执行，并通过统一任务/通知或拥有模块界面呈现结果。
- 可以使用 Fake Model Adapter 验证超时、限流、结构错误、敏感输入和人工确认语义，而不调用真实模型。

## 禁止的假设

- 不创建客户、线索、订单、员工绩效、销售分配、职业规划或其他具体 AI 用途、字段、Prompt 和评价标准。
- 不把脱敏自动视为允许向境外模型发送数据，也不因使用国内模型就跳过数据最小化和授权。
- 不允许 AI 输出直接修改领域表、审批结果、权限、价格、财务、人员状态或其他业务事实。
- 不允许 AI 网关执行任意 URL、SQL、脚本、文件操作、MCP 工具或未注册业务命令。
- 不把 Prompt/响应正文默认写入 PostgreSQL、日志、Sentry、Trace、死信或审计详情。
- 不在第一阶段引入 LiteLLM、LangChain/LangGraph、向量数据库、RAG 平台、Agent 平台或 Prompt 低代码设计器。

## 决策

### 1. 使用“拥有模块用途 + AI 网关 + Provider Adapter”

```text
拥有模块
  AI 用途语义 / 最小输入 / 资源授权 / 人工确认后的正式命令
        ↓
platform-sdk + contracts/ai
        ↓
ai-gateway
  用途注册 / 数据策略 / Prompt版本 / 模型路由 / 预算 / 输出校验 / 调用记录
        ↓
integration-runtime
  Deadline / 限流 / 重试分类 / 熔断 / Trace / 技术错误
        ↓
Provider Adapter
  官方 SDK/REST / 模型参数 / 错误码 / 用量 / 供应商幂等
        ↓
托管模型服务
```

- 拥有模块定义“为什么调用 AI、允许提供什么数据、输出如何解释、谁可以确认以及确认后执行什么正式命令”。
- `ai-gateway` 提供业务中立的调用、治理和证据边界，不拥有客户、订单、人员、任务或其他领域事实。
- `integration-runtime` 只复用外部调用的韧性、安全和可观测原语，不拥有 Prompt、模型策略、Token 成本或人工确认。
- Provider Adapter 位于 `apps/api`/`apps/worker` 组合边界，领域模块不得导入模型 SDK。
- 第一阶段不创建真实 Provider Adapter；Fake Adapter 只返回明确标记的合成结果。

### 2. 自研、开源与托管边界

| 能力 | 选择 | 原因 |
|---|---|---|
| 用途注册、数据策略、Prompt 发布、路由、预算、调用记录和人工确认语义 | 自研轻量 `ai-gateway` | 需要与项目授权、领域所有权、审计、数据治理和契约一致 |
| 输入/输出结构 | JSON Schema 2020-12 + Ajv | 使用已确认开放标准和成熟开源验证器，不自研 Schema 语言 |
| Prompt 插值 | 受限、无脚本的模板能力，具体库实施时锁定 | 禁止任意表达式、网络访问和代码执行 |
| 外部调用韧性 | 复用自研 `integration-runtime` 与开源 HTTP/Telemetry 能力 | 避免第二套超时、重试、限流、脱敏和 Trace 实现 |
| 模型协议 | 供应商官方 SDK 或官方 REST，经 Adapter 隔离 | 复用官方兼容能力，不让供应商 DTO 进入平台契约 |
| 模型推理 | 后续批准的托管模型服务 | 项目不自研基础模型或 GPU 推理平台 |
| LiteLLM | 第一阶段不采用 | 增加 Python 服务和重复路由/配置/观测层，当前供应商与复用需求不足 |
| LangChain/LangGraph/Agent 框架 | 第一阶段不采用 | 当前没有经批准的多步 Agent/工具调用场景，引入会扩大隐式控制流和安全面 |

当真实接入达到多个供应商、复杂兼容矩阵或独立代理运维需求时，可以重新评估 LiteLLM；重新评估不得削弱本 ADR 的用途、数据和人工确认边界。

### 3. AI 用途必须先注册

每个 `AiUseCase` 或等价用途在实施前必须确认：

- 稳定用途标识、Owner、目标用户和明确非目标。
- 输入 JSON Schema、数据分类、允许字段、来源和最小化规则。
- 输出 JSON Schema、置信/不确定性表达、展示方式和禁止解释。
- Prompt 源资产 Owner、发布/回滚权限、评审人和测试集。
- 允许模型/供应商/地域、数据保留、跨境、训练使用和退出要求。
- 同步/异步、Deadline、最大 Token、成本预算、并发和限流。
- 人工确认是否必需、谁能确认、过期条件以及确认后的正式领域命令。
- 失败、拒绝、超时、内容安全、结构错误、降级和用户提示。

未注册用途不得通过通用 `generate(prompt)` 绕过治理。用途注册是技术治理资产，不等于业务规则已经批准；业务语义仍由拥有模块和正式规则所有。

### 4. Prompt 版本与业务语义分离

- 拥有模块拥有 Prompt 的业务语义、输入含义、输出解释和验收集。
- `ai-gateway` 可以保存或登记不可变 Prompt 发布制品、内容摘要、模板变量 Schema、Owner、评审状态和生效策略。
- 草稿可修改，发布版本不可原地修改；回滚通过重新选择历史发布或发布新版本完成。
- Prompt 变量必须来自注册输入 Schema，不允许任意对象序列化、远程内容自动拼接或脚本 Helper。
- 运行记录保存准确用途、Prompt 版本、模型路由策略和输出 Schema 版本，不能只记录“当前 Prompt”。
- Prompt 内容本身可能包含内部策略，访问、日志、导出和保留必须授权；不得把 System Prompt 返回普通客户端。
- 当前不创建任何 CRM Prompt、Prompt 表字段或管理页面，具体存储模型等待第一个真实用途验证。

### 5. 数据最小化、脱敏与地域策略

- 输入由拥有模块按允许列表构造，AI 网关再次执行 Schema、大小、数据分类和禁止字段校验。
- 默认使用合成、匿名化或最小必要内容；不把完整领域对象、数据库行、时间线、附件或聊天历史直接传入模型。
- 通用正则脱敏只能作为补充，不能替代拥有模块的字段级允许列表和数据分类。
- 匿名化、假名化和脱敏是不同处理；仍可关联个人的数据继续按个人数据治理。
- 海外模型只可用于不含真实客户/员工/业务敏感数据的开发测试，使用合成数据。
- 生产模型、地域、跨境、供应商训练/保留和数据处理协议必须逐用途批准；“脱敏后自动允许海外调用”不成立。
- 供应商不得使用输入/输出训练其模型，除非公司另行明确批准且满足告知、授权和合同要求。
- 文件、图片、音频和知识库内容进入模型前需要独立数据类型、恶意内容和版权评审；第一阶段不实现多模态或 RAG。

### 6. 输出是非权威建议

- 模型输出先作为 `AiProposal` 或等价非权威结果，由 AI 网关进行大小、JSON Schema、内容安全和引用完整性校验。
- 结构校验通过只代表格式有效，不代表事实正确、资源存在、操作有权限或业务状态允许。
- 需要业务影响的输出必须由受权人员明确查看并确认；确认动作保存主体、时间、用途、版本、结果引用和必要理由。
- 确认后由拥有模块重新读取权威状态、重新授权并执行正式命令；AI 网关不能直接写领域表。
- 拒绝、修改后采用和忽略也是独立结果，可用于质量评估，但不自动训练或修改 Prompt。
- 高风险用途如权限、财务、价格、审批、绩效、人员处置和法律/健康建议默认禁止自动执行，未来放宽必须单独 ADR 和风险批准。

“需要人工确认”不能只表现为 UI 文案；服务端契约必须阻止未确认 Proposal 产生正式业务副作用。

### 7. 调用记录、内容保留和审计

默认调用记录只保存：

- 用途、环境、发起主体/应用、稳定资源引用和授权上下文摘要。
- Prompt/输入/输出 Schema 版本，模型策略、Provider/模型版本和 Adapter 版本。
- 请求幂等键、状态、时间、耗时、重试/尝试、Token 用量、供应商费用/项目成本估算和错误类别。
- 数据策略版本、脱敏/阻止结果、输入/输出安全摘要和 Trace 引用。
- Proposal 引用、是否需要人工确认以及确认/拒绝/修改结果引用。

默认不保存完整输入、Prompt 渲染结果、模型原始响应、思维链、供应商调试载荷或用户敏感内容。若某用途确需内容留存，必须单独确认字段、目的、权限、加密、地域、保留和删除，并避免把供应商私有推理过程作为产品数据。

- 技术调用记录不替代领域审计；正式业务动作仍由拥有模块和 `audit` 记录。
- AI 调用、Prompt 发布、模型策略、预算、人工确认和管理员重放分别授权并审计。
- 日志、Sentry 和 Trace 只记录安全元数据，不记录 Prompt 或模型完整输出。

### 8. 同步、异步、幂等与重试

- 默认长耗时或非交互任务走“拥有模块本地事务 → Outbox → RabbitMQ → Worker → AI Adapter”。
- 只有当前交互必须立即返回建议时允许同步调用，并声明严格 Deadline、取消和失败体验。
- 相同幂等键可以去重业务请求，但模型输出具有非确定性；不能宣称重试会产生相同内容。
- 网络超时后结果不明时，除非供应商支持幂等键或状态查询，否则不得盲目自动重试并产生重复费用/Proposal。
- 429、暂时连接错误和部分 5xx 只在用途策略允许、Retry Budget 内重试；内容拒绝、输入违规、结构错误和预算超限不自动重试。
- Worker 每次调用前重新检查用途启用、资源状态、权限/授权快照有效性、预算和取消状态。
- 取消是尽力而为；已发送供应商的调用可能仍产生费用，迟到结果必须按用途状态安全丢弃或隔离。

### 9. 模型路由、降级和成本

- 路由依据用途、环境、数据分类、地域、能力、上下文长度、结构化输出支持、价格、延迟和健康状态。
- 路由结果必须可追溯到策略版本；领域模块不能直接指定任意供应商或未经批准模型。
- 自动 Fallback 只在候选模型具有相同或更严格数据政策且用途明确允许时发生，不允许从国内策略静默切换到海外模型。
- 模型升级先通过固定合成测试集、结构契约、安全用例、成本与延迟比较，再逐步发布。
- 预算按用途、环境和适当主体设置硬/软限制；预算耗尽的失败行为显式定义，不能无限调用。
- Provider 上报 Token 和费用作为技术计量；经营财务事实仍由未来正式财务领域拥有。

### 10. Prompt Injection、工具和不可信内容

- 用户输入、网页、文件、知识库、供应商输出和模型输出均视为不可信内容，不因被放入 Prompt 就获得指令权限。
- System/Developer 指令、业务数据和外部内容使用明确边界；模型输出必须经过 Schema 与业务校验。
- 第一阶段 AI 网关不提供工具调用、浏览、代码执行、SQL、文件系统、MCP 或领域命令执行。
- 未来工具必须逐个注册用途、输入 Schema、对象授权、幂等、超时、预算、审计和人工确认；每次实际调用由服务端重新授权。
- 模型永远不能获得 Keycloak Token、Cookie、数据库连接、COS Secret、Sentry Token、服务器 Secret 文件或万能平台凭据。

## 授权与审计

- AI 用途调用、敏感用途调用、Prompt 发布、模型策略、预算管理、内容查看、人工确认和管理员重放使用不同授权能力。
- 调用方必须同时满足功能权限、资源权限、数据范围和用途策略；AI 网关不因拥有调用权限就绕过领域授权。
- 人工确认记录实际确认主体和当时有效上下文，不使用 AI 发起主体替代人类责任人。
- 所有管理员变更保存原因、差异、版本、生效范围、操作者和审计引用。
- 未确认具体角色和权限代码前不创建伪权限名称或默认管理员。

## 可观测性

- 指标覆盖用途/模型的调用量、等待、延迟、Token、成本、限流、预算拒绝、错误类别、结构失败、安全阻止、Fallback 和人工采纳结果。
- Trace 连接拥有模块、Outbox、RabbitMQ、Worker、AI 网关和 Provider Adapter，只使用安全引用。
- 日志/Sentry 不记录完整输入、Prompt、输出、Token/Secret、客户信息或供应商调试载荷。
- 告警关注持续错误、费用异常、数据策略阻止突增、模型版本回归和队列积压，不因单次正常拒绝直接告警。

## 测试与验收

- Fake Adapter 支持确定性 Fixture、延迟、429、5xx、内容拒绝、畸形 JSON、超大输出、迟到响应和用量异常。
- 契约测试覆盖输入/输出 Schema、Prompt 版本、路由策略、供应商错误映射和 Adapter 兼容。
- 安全测试覆盖 Prompt Injection、禁止字段、敏感数据、超长输入、恶意 Unicode、未知输出字段和工具诱导。
- 治理测试覆盖未注册用途、未批准模型、预算超限、无权调用、未确认执行、过期 Proposal 和人工拒绝。
- 故障测试覆盖 RabbitMQ/Redis/PostgreSQL/Sentry/Provider 不可用、网络超时、重复消息和轮换 Secret。
- 真实 Provider 上线前使用合成测试集评估质量、稳定性、成本、延迟和数据保留，不使用真实客户数据试跑。

## 已考虑的方案

### 每个业务模块直接调用模型 SDK

初期简单，但会产生不同的数据、Prompt、日志、预算、重试和人工确认实现，并让供应商类型进入领域代码，因此不采用。

### LiteLLM 作为统一模型代理

模型兼容和路由能力成熟，但会增加 Python 运行时和另一套配置/观测控制面，且不能替代本项目的数据治理、授权和人工确认，因此第一阶段不采用。

### LangChain/LangGraph 或通用 Agent 平台

适合多步 Agent 和工具编排，但当前没有确认用途，隐式控制流和工具安全成本过高，因此不采用。

### 自研轻量 AI 网关加独立 Adapter

保持 Node 24、模块契约和治理边界显式，同时可在供应商复杂度增长后替换底层模型代理，因此采用。

## 影响与已接受风险

- 项目需要维护用途注册、Prompt 版本、数据策略、模型路由、预算、调用记录和人工确认基础能力。
- 不采用 LiteLLM 会增加少量 Provider Adapter 工作，但避免额外服务和重复治理层。
- 默认不保存完整内容会降低部分问题复现能力，需要合成 Fixture、安全摘要和经批准的临时诊断机制补偿。
- 模型行为具有非确定性，即使版本固定也需要持续测试、抽检和人工责任。

## 第一阶段范围

- 建立 `ai-gateway` 模块、供应商中立契约、治理边界和 Fake Adapter 约定。
- 定义用途注册、数据策略、Prompt/模型版本、调用元数据、预算和人工确认语义方向。
- 验证业务中立 walking skeleton：合成输入 → Fake Adapter → Schema 校验 → 非权威 Proposal → 模拟人工确认边界。
- 不创建真实模型账号、Secret、Provider Adapter、生产调用、CRM Prompt、向量库、知识库或工具调用。

## 待后续确认

- 第一个真实 AI 用途、Owner、用户、输入/输出和验收集。
- 模型供应商、地域、合同、数据保留、训练使用、费用和退出方案。
- `AiUseCase`、Prompt Release、调用记录、Proposal 和人工确认的具体契约与存储模型。
- Prompt 模板库、内容安全、Token 估算和成本核算的具体依赖。
- 是否以及何时引入 LiteLLM、RAG、多模态或工具调用。

## 非目标

- 本 ADR 不定义客户评级、摘要、绩效、分配、审批、财务或其他业务 AI 规则。
- 本 ADR 不批准真实客户/员工数据发送给任何模型供应商。
- 本 ADR 不创建运行时 Agent、自主决策者、聊天机器人、知识库或模型训练平台。
- 本 ADR 不允许 AI 绕过人类责任、正式授权和拥有模块业务不变量。
