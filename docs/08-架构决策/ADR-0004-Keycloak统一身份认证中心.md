# ADR-0004：Keycloak 统一身份认证中心

- 状态：已接受
- 日期：2026-07-22
- 决策人：项目负责人
- 适用范围：所有需要登录身份的应用与服务

## 背景

历史方案计划在业务系统内保存密码，自行签发 JWT Access Token，并在 Redis 中管理 Refresh Token。认证涉及密码策略、多因素认证、暴力破解防护、会话、令牌轮换、注销、单点登录和安全审计，是高风险且容易被低估的基础能力。

项目将主要由 AI 持续开发，并逐步从 CRM 扩展为公司工作台。认证协议和凭证生命周期不应由各应用重复实现，同时业务组织和数据授权也不能被身份产品的数据模型锁定。

## 决策

1. 使用开源 Keycloak 作为统一身份提供商（Identity Provider）和认证中心。
2. Keycloak 负责凭证、密码策略、多因素认证、暴力破解防护、登录会话、单点登录、Token 签发与刷新、注销以及认证事件。
3. 应用使用标准 OpenID Connect/OAuth 2.0 协议接入 Keycloak，不实现自有密码校验、JWT 签发或 Refresh Token 存储系统。
4. `packages/platform-modules/auth-context` 验证 Token 的签发者、受众、签名、有效期及必要声明，并将外部身份转换为内部、与传输无关的主体上下文。
5. Keycloak 的 `issuer + sub` 是外部认证身份的稳定标识。它与内部人员、组织和有效期任职的关联由项目平台层管理；本 ADR 不提前规定关联表结构。
6. Keycloak 不作为完整业务授权和数据范围的事实源。业务授权由 `authorization` 平台模块裁决，组织与任职由 `organization` 平台模块管理。
7. 领域模块不得直接调用 Keycloak API、读取 Keycloak 表或依赖 Keycloak SDK，只能通过主体上下文、正式契约或 `platform-sdk` 使用身份信息。
8. Keycloak Realm、Client、Protocol Mapper、安全策略和回调地址必须配置即代码、版本化并按环境发布。秘密值只使用配置引用，不写入仓库。
9. Keycloak 版本必须固定；升级先经过测试环境的登录、Token、注销、密钥轮换、备份恢复和兼容性验证。
10. 不修改 Keycloak 源码。确需扩展时优先使用标准协议、外部适配器或边界清晰的 SPI，并单独评审升级风险。

## 认证与授权边界

| 能力 | 所有者 |
|---|---|
| 登录、密码、MFA、SSO、会话、Token | Keycloak |
| Token 验证和内部主体上下文 | `auth-context` |
| 人员、组织、岗位、有效期任职 | `organization` |
| 功能权限、资源动作、数据范围 | `authorization` |
| 业务规则和业务状态 | 对应领域模块 |

Keycloak 返回的角色或 Claim 可以作为协议输入，但不能绕过内部授权服务直接成为业务访问结论。

## 安全与失败行为

- Token 验证必须失败关闭；签名、签发者、受众、有效期或必要声明不合法时拒绝访问。
- 公钥发现和缓存需要支持 Keycloak 密钥轮换，并定义超时、缓存和不可用行为。
- 日志不得记录密码、完整 Token、授权码、Client Secret 或其他认证凭证。
- 认证成功不等于拥有业务权限，也不等于对应员工或任职仍然有效。
- Keycloak 不可用时，系统不得退化为绕过认证；已经签发 Token 的离线验证策略和强制失效需求在会话方案中另行确认。

## 已考虑的方案

### 自建账号密码、JWT 和 Refresh Token

表面上便于定制，但需要长期承担密码、会话、令牌轮换、MFA、漏洞响应和账号恢复的安全责任。该能力不构成 CRM 的差异化价值，也不适合由 AI 自行实现，因此不采用。

### 商业托管身份服务

可以降低部分运维负担，但会引入持续费用、数据与配置迁移成本以及供应商依赖。当前优先选择可自托管的 Keycloak，并通过协议和适配器保留未来替换能力。

## 影响

- 部署环境需要增加 Keycloak 及其数据库、监控、备份、恢复和升级流程。
- 本地与测试环境需要可重复初始化的 Realm 和 Client 配置。
- 账号生命周期与员工入转调离之间需要后续定义同步和失效流程。
- PC Web 与多客户端会话模式后来分别由 ADR-0005、ADR-0017 确认；内部人员与企微身份关联由 ADR-0018 确认。服务间认证、内部 Keycloak 账号恢复及外部微信账号生命周期仍需分别确认。
- 替换身份提供商时，领域模块不应变化；主要改动应限制在部署、配置和 `auth-context` 适配器。

## 非目标

- 本 ADR 不决定浏览器使用 BFF Cookie 还是直接持有 OIDC Token。
- 本 ADR 不决定企微、微信或其他第三方身份的绑定方式。
- 本 ADR 不定义业务角色、权限码、数据范围或组织结构。
- 本 ADR 不选择 Keycloak 的具体补丁版本和高可用部署拓扑。
