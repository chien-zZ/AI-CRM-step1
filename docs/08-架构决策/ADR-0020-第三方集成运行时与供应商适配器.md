# ADR-0020：第三方集成运行时与供应商适配器

- 状态：已接受
- 日期：2026-07-23
- 决策人：项目负责人
- 适用范围：`packages/platform-modules/integration-runtime`、`apps/api`、`apps/worker`、未来供应商适配器与集成契约
- 依赖决策：ADR-0003、ADR-0006、ADR-0010、ADR-0011、ADR-0014

## 已知事实

- 项目未来可能接入企微、微信、短信、支付、课程平台、题库和其他第三方系统，但当前未确认供应商、账号、凭据、回调域名或验收场景。
- Keycloak、Flowable、COS、ClamAV、RabbitMQ 和 Redis 已经分别通过明确边界接入，不能被一个新“集成网关”重新收编为共享业务模型。
- 第一阶段通知只实现 PC 站内通知，不代表企微、短信或微信渠道已经进入交付。
- 支付流水、订单、人员、通知和 AI 输出具有不同事实所有者和失败语义，不能由通用集成模块拥有。
- 项目使用 Node 24、PostgreSQL、RabbitMQ、Redis、OpenAPI/JSON Schema 和 OpenTelemetry 方向的可观测边界。

## 允许的假设

- 多数外部调用需要复用超时、重试分类、限流、熔断、日志脱敏、Trace 和测试桩。
- 入站 Webhook 普遍需要原始报文、供应商验签、时间戳/Nonce、防重放、耐久接收和异步处理。
- 业务模块可以先定义供应商中立 Port，由组合根注入具体 Adapter。

## 禁止的假设

- 不把历史材料中的支付、短信、企微或 AI 集成视为第一阶段已确认范围。
- 不建立包含所有供应商字段、业务映射和业务状态的巨型“集成网关”数据库。
- 不允许领域模块直接导入供应商 SDK、直接读取集成记录表或绕过正式 Port 调用外部 API。
- 不把供应商响应、回调或发送成功直接视为订单成功、人员离职、消息已读或其他业务事实。
- 不创建没有真实凭据、测试账号、官方文档和验收 Owner 的伪适配器。

## 决策

### 1. 使用“通用运行时 + 拥有模块 Port + 独立 Adapter”

```text
拥有模块：业务规则、资源事实、供应商中立 Port
                         ↓
integration-runtime：超时、韧性、验签框架、追踪、错误分类
                         ↓
Provider Adapter：官方协议、SDK/REST、字段转换、供应商幂等
                         ↓
第三方系统
```

- 拥有模块定义能力语义和 Port，例如“发送通知”“同步目录”“发起支付”或“查询外部状态”，不能定义为任意 `callProvider`。
- `integration-runtime` 只提供业务中立技术原语，不拥有业务对象、供应商字段映射或领域状态。
- 具体 Adapter 位于 `apps/api`、`apps/worker` 的组合边界，或在出现明确复用与独立发布需求后通过新 ADR 建立专用 Adapter 包。
- 领域模块只依赖自己的 Port、正式契约和 `platform-sdk`，不依赖 Adapter 或供应商 SDK。
- `apps/api` 组合同步调用和 Webhook 入口；`apps/worker` 组合异步出站、重试、对账和长耗时 Adapter。

当前不新增顶层 `packages/integration-adapters/` 目录，避免在没有真实供应商时改变 ADR-0003 的仓库分层。

### 2. `integration-runtime` 自研范围保持轻量

通用运行时可以提供：

- 基于绝对 Deadline 的连接、响应和总超时。
- 按操作安全性区分的重试、退避、抖动和 Retry Budget。
- 并发限制、供应商/租户速率限制、熔断和恢复探测。
- 项目统一的请求关联、Trace、指标、日志脱敏和供应商错误分类。
- 幂等键、请求指纹、原始响应摘要和安全诊断引用。
- Webhook 原始报文读取、验签接口、时间戳/Nonce、防重放和确认策略框架。
- 可替换的凭据解析接口，只接收秘密引用，不拥有 Secret 明文配置。
- Fake/Stub Adapter、故障注入和契约测试工具。

运行时不得提供任意流程编排器、通用字段映射语言、跨系统主数据、万能重试按钮或供应商业务控制台。

### 3. 出站调用按同步与异步明确分流

默认使用异步链路：

```text
拥有模块本地事务
  → Transactional Outbox
  → RabbitMQ
  → apps/worker
  → Provider Adapter
  → 结果/状态经正式命令或事件返回拥有模块
```

- 业务事务不等待非必要的供应商网络调用。
- Worker 在调用前重新检查权威业务状态；过期、取消或已完成的请求无副作用结束。
- 只有用户当前请求必须立即获得外部结果时才允许同步调用，并必须声明 Deadline、可重试性和失败对用户的影响。
- 未提供幂等保证的非幂等写调用默认不自动重试；需要供应商幂等键、查询确认或补偿方案后才能重试。
- 供应商调用成功只形成集成结果，不直接修改另一个模块的业务表。

### 4. Webhook 先验证和耐久接收，再异步处理

入站 Webhook 执行以下顺序：

1. 按供应商要求保留原始报文、必要请求头和接收时间。
2. 在信任或反序列化业务字段前验证签名、时间戳、Nonce、目标环境和凭据版本。
3. 使用供应商事件 ID、请求指纹或经评审组合键做耐久防重。
4. 在 PostgreSQL 中登记接收事实、验证结果和处理状态；Redis 只能作为短期重放加速。
5. 按供应商协议在耐久接收后尽快返回确认，再通过 RabbitMQ/Worker 处理业务影响。
6. Worker 调用拥有模块的正式命令；拥有模块重新验证资源、状态、金额、主体和幂等条件。

如果供应商协议无法“先耐久再确认”，Adapter 必须在独立评审中记录风险、超时和补偿方式。仅依赖来源 IP、User-Agent 或 TLS 不能替代供应商签名。

### 5. 技术接收记录与业务事实分离

- `integration-runtime` 可以拥有供应商无关的技术调用尝试、Webhook 接收和重放防护事实。
- Provider Adapter 可以拥有最小的供应商游标、外部请求/事件引用和对账水位，但不得复制完整业务对象。
- 拥有模块保存自己的业务状态及稳定外部引用；其他模块不得查询集成表推断业务结果。
- 支付流水必须由未来支付/财务领域拥有，并与订单通过正式关联和对账处理；通用集成运行时不拥有金额、支付状态或退款规则。
- 通知中心拥有通知和渠道投递尝试；“供应商已接收”不等于用户已读。
- 企微通讯录输入由组织适配边界处理；目录删除不等于 Employment 失效。
- AI 请求、脱敏、模型选择和人工确认具有独立治理要求，另立 ADR，不并入本运行时的普通供应商语义。

### 6. Port、Adapter 与配置边界

- Port 使用项目稳定类型、资源引用、幂等键和错误语义，不暴露供应商 DTO、SDK Client 或 HTTP 状态细节。
- Adapter 负责供应商字段、签名、分页、游标、错误码和 API 版本转换。
- 供应商 Endpoint、账号、租户和功能开关属于技术配置；Client Secret、证书和签名密钥只使用秘密引用。
- 业务配置中心不得保存 Secret，也不得让运行时动态执行任意 URL、脚本或表达式。
- 多环境使用独立账号、回调地址、密钥和数据；测试环境不能调用生产供应商账户。
- API 版本和 Adapter 版本固定并记录兼容矩阵，升级需要契约与回放测试。

### 7. 重试、熔断与对账不是业务成功

- 重试策略由操作类别和供应商契约决定，不能全局统一“失败重试三次”。
- `429`、超时、连接错误、部分 `5xx` 可作为候选临时错误；认证失败、验签失败、业务拒绝和不合法请求默认不自动重试。
- 熔断只保护系统和供应商，不改变业务状态；熔断期间请求进入明确失败、排队或稍后处理状态。
- 达到重试上限后进入死信/人工处置，并保留安全重放入口和原因。
- 对账从供应商权威查询或文件重新核对，不从历史调用日志猜测最终业务状态。
- 所有人工重放、跳过、修复映射和对账确认都需要授权、理由和审计。

## 自研、开源与托管边界

| 能力 | 选择 | 原因 |
|---|---|---|
| Port、运行时编排、错误分类和项目审计 | 自研轻量层 | 需要符合本项目模块、契约、幂等和可观测边界 |
| HTTP、TLS、密码学和 JSON 校验 | Node 24 标准能力及成熟开源库 | 不自研协议栈和密码学算法 |
| 异步、短期协调与耐久记录 | RabbitMQ、Redis、PostgreSQL | 已确认基础设施，分别承担传输、协调和事实 |
| Trace、指标和日志关联 | OpenTelemetry 生态与结构化日志库 | 使用行业标准，避免私有观测协议 |
| 供应商协议 | 官方 SDK 或官方 REST API，经 Adapter 隔离 | 复用官方兼容能力，同时避免供应商类型进入领域代码 |
| Secret 管理 | 部署阶段选择托管或自建秘密管理，经统一接口接入 | Secret 生命周期和轮换不应由业务配置中心承担 |

不采用 n8n、Node-RED、Apache Camel 作为认证、支付或核心业务集成执行引擎。它们未来可用于经批准的低风险内部自动化，但不能成为业务事实源、绕过契约或保存核心 Secret。

不使用 Kong 等 API 网关替代应用内的验签、幂等、对象级授权和业务校验。边缘网关可以提供 TLS、路由、基础限流和 WAF，但不了解领域事实。

### 8. 现有适配器保持原所有权

- Keycloak/OIDC 与企微微信身份适配继续执行 ADR-0004、ADR-0006、ADR-0017。
- Flowable 继续由 Workflow Facade 隔离。
- COS 与 ClamAV 继续由文件中心 Adapter 隔离。
- RabbitMQ/Redis 继续由事件与可靠消息模块封装。
- 这些模块可以复用 `integration-runtime` 的通用技术原语，但不得迁移事实所有权或让领域模块依赖运行时。

## 安全、隐私与审计

- 出站数据必须按最小必要字段构造；敏感数据出境、跨境、脱敏和供应商留存要求在启用前评审。
- 日志、Trace、指标和死信不得记录 Secret、完整 Token、支付凭证、个人敏感信息或未经脱敏的原始载荷。
- 原始 Webhook 或供应商响应如需留存，必须加密、限权、定义保留时间并与业务数据分离。
- SSRF 防护限制目标域名、协议、DNS/IP 范围和重定向；运行时不接受业务配置传入任意 URL。
- 供应商账号、密钥、证书、回调配置和人工重放操作全部纳入审计。
- Adapter 只获得自身需要的 Secret 和网络权限，不共享万能供应商账号。

## 可观测性与测试

- 指标覆盖供应商/操作的请求量、延迟、超时、错误类别、重试、熔断、限流、Webhook 验签、防重、积压、死信和对账差异。
- Trace 从业务请求/事件贯穿 Outbox、RabbitMQ、Worker 和 Provider Adapter，使用安全外部引用关联，不记录凭据。
- 单元测试覆盖错误分类、Deadline、Retry Budget、退避、熔断状态和脱敏。
- 契约测试使用供应商 Sandbox、录制并脱敏的 Fixture 或协议模拟器，不能只 Mock “成功”。
- Webhook 测试覆盖正确/错误签名、旧时间戳、Nonce 重放、乱序、重复、未知版本、快速确认和处理失败。
- 故障测试覆盖 DNS、连接拒绝、慢响应、半开连接、429、5xx、RabbitMQ/Redis/PostgreSQL 故障和凭据轮换。

## 已考虑的方案

### 一个巨型集成网关拥有所有供应商与业务映射

入口集中但会混合支付、身份、通知、组织和 AI 的事实，形成共享数据库与发布瓶颈，因此不采用。

### 每个业务模块自行封装 HTTP 和重试

初期简单，但会产生不同的超时、验签、重试、脱敏和观测实现，AI 并行开发时尤其容易漂移，因此不采用。

### 使用低代码自动化平台执行核心集成

可快速连通 SaaS，但核心规则、Secret、重试和审计会落在仓库契约之外，难以测试和版本化，因此不采用。

### 轻量运行时加独立 Adapter

复用稳定技术能力，同时保持业务和供应商边界清晰，因此采用。

## 影响

- 仓库新增 `integration-runtime` 平台模块骨架和 `contracts/integrations/` 契约类别，但不新增具体供应商 Adapter。
- 未来每个供应商都需要 Owner、Sandbox/测试账号、官方协议、Secret、数据范围、超时、重试、对账和退出方案。
- Provider Adapter 不能成为跨模块业务编排层；跨业务事实仍通过正式命令和事件协作。
- AI 网关已由后续 ADR-0024 单独确认；支付领域和外部通知渠道仍需各自确认。AI 治理保持独立，不并入通用集成运行时。

## 第一阶段范围

- 建立模块边界、供应商中立契约目录、错误分类、测试桩和安全/可观测要求。
- 实现任务启动后可建设通用 HTTP 执行器、Webhook 验签接口和故障注入工具，但具体库和 API 先经契约评审。
- 不创建支付、短信、企微推送、微信消息、课程平台、题库或 AI Adapter。
- 不申请第三方生产账号、创建回调地址或提交真实敏感数据。

## 待后续决策

- 首个真实第三方集成及其能力 Owner、供应商和验收场景。
- `integration-runtime` 具体公开 API、错误分类、存储模型和迁移。
- HTTP/韧性/Telemetry 依赖的具体库与版本。
- Secret 管理、出站网络控制、代理、证书和回调域名部署方案。
- AI 网关的数据治理、模型路由和人工确认边界：已由 ADR-0024 解决；具体真实用途和 Provider 仍待确认。

## 非目标

- 本 ADR 不确认支付、短信、企微推送、微信通知或 AI 功能进入第一阶段。
- 本 ADR 不定义支付流水、订单、客户、人员或消息业务字段。
- 本 ADR 不创建供应商 SDK 封装、Webhook 端点或真实调用代码。
- 本 ADR 不允许通过通用运行时执行任意 URL、脚本或未评审工作流。
