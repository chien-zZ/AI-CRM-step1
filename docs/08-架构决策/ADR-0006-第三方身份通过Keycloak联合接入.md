# ADR-0006：第三方身份通过 Keycloak 联合接入

- 状态：已接受
- 日期：2026-07-22
- 决策人：项目负责人
- 适用范围：企微、微信及未来第三方登录提供商
- 依赖决策：ADR-0004、ADR-0005

## 背景

历史方案以 CRM 自建账号密码为根身份，在业务数据库维护 `account_oauth_binding`，使用一次性 `bind_ticket` 把企微 `userid` 或微信 `openid` 绑定到应用账号。

项目现已确认 Keycloak 是统一身份提供商。若继续在 CRM 内实现第三方登录、绑定和会话签发，就会形成两个认证事实源，并让业务系统承担账号接管、串号、解绑恢复和提供商协议变化等安全责任。

## 决策

1. Keycloak 用户是唯一认证主体。企微、微信及未来第三方身份只作为 Keycloak 用户的联合身份或快捷登录入口。
2. 支持标准 OpenID Connect 或 SAML 的提供商优先使用 Keycloak Identity Brokering 标准能力。
3. 对企微、微信等非标准提供商，使用边界清晰的外部适配器或经过安全与升级评审的 Keycloak SPI。不得修改 Keycloak 源码。
4. 第三方身份验证成功后仍由 Keycloak 签发 Token；BFF 只接受 Keycloak 建立的可信认证结果，不能绕过 Keycloak 直接创建已登录主体。
5. CRM 和其他领域模块不建设平行的第三方认证表、`bind_ticket` 登录链路或外部身份 Token 签发逻辑。
6. 外部身份的可信标识只能来自服务端与提供商完成的 OAuth、OIDC、SAML 或等价协议交换结果。不得信任前端直接提交的 `userid`、`openid`、`unionid` 或其他外部主体标识。
7. 同一个提供商和外部主体标识不能同时关联多个 Keycloak 主体。绑定冲突必须失败关闭并进入安全审计，不能自动覆盖原关联。
8. 绑定、解绑、换绑和管理员代操作必须要求适当的重新认证或受控管理流程，并记录操作人、目标主体、提供商、结果、原因、时间和 Trace ID。
9. 不得仅凭未验证的手机号、邮箱、姓名或前端声明自动合并账号。首次登录的关联策略需要按提供商和人员生命周期单独确认。
10. 外部提供商的 Access Token、Refresh Token 和 Client Secret 必须最小化保存。确需保存时只能位于认证适配边界并加密、限权、可轮换；领域模块不可读取。
11. 第三方登录身份不能直接授予组织成员资格、岗位、业务角色或数据范围。登录后仍需内部人员关联和授权模块裁决。
12. 企微 `userid`、微信 `openid` 等如果同时用于消息投递，应由通知渠道地址或组织同步能力通过正式接口管理，不得由通知模块读取 Keycloak 数据库。

## 组件边界

| 能力 | 所有者 |
|---|---|
| 第三方 OAuth/OIDC/SAML 协议适配 | Keycloak Identity Broker、外部适配器或已评审 SPI |
| 联合身份关联与认证流程 | Keycloak |
| PC Web 登录会话 | `apps/api` BFF |
| 内部人员和任职关联 | `organization` |
| 业务权限和数据范围 | `authorization` |
| 企微/微信消息投递地址 | `notifications` 或组织同步适配器 |
| 业务身份与业务状态 | 对应领域模块 |

## 安全与失败行为

- 提供商不可用、回调校验失败、`state`/`nonce` 不合法或外部身份冲突时，联合登录失败，不得回退为猜测匹配。
- 标准 Keycloak 登录是否继续可用由产品范围决定，但第三方提供商故障不能破坏已有根身份数据。
- 认证日志不得记录完整外部 Token、授权码、Client Secret 或不必要的外部标识明文。
- 关联与解绑操作需要幂等，重复回调不能创建重复关联或多条有效关系。
- 管理员代解绑不能静默发生，必须保留可调查的审计证据和恢复流程。
- 提供商适配器升级需要覆盖首次登录、已有绑定、冲突、解绑、重复回调、超时和提供商故障测试。

## 已考虑的方案

### CRM 自建 `account_oauth_binding` 与 `bind_ticket`

可以完全控制表结构和交互，但会在 Keycloak 之外形成第二套认证与关联事实源，并需要自行承担绑定安全、Token 生命周期和账号恢复，因此不采用。

### Keycloak 联合身份

保持统一认证主体和 Token 签发边界，CRM 只消费内部主体上下文。非标准提供商仍需要适配工作，但其风险被限制在认证边界，因此采用。

## 影响

- 历史 CR-11 中 CRM 自建第三方绑定表和登录端点不再是当前设计依据。
- 企微、微信接入前需要评估官方协议、Keycloak 兼容方式、适配器维护成本和版本升级风险。
- 内部人员与企微身份的关联/解绑后来由 ADR-0018 确认；提供商登录开通顺序、外部主体允许的绑定数量、首次关联和账号恢复仍需分别确认。
- 通知渠道地址与登录身份需要通过受控接口关联，但二者不能共用数据库表作为隐式集成。

## 非目标

- 本 ADR 不确认第一阶段必须接入哪些第三方提供商。
- 本 ADR 不定义企微工作台 H5 或微信外部端的产品范围。
- 本 ADR 不决定一个主体可以关联多少个外部身份。
- 本 ADR 不定义人员、员工、岗位和组织成员关系的数据模型。
