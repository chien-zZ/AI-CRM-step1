# ADR-0008：自研有效期化人员与组织模型

- 状态：已接受
- 日期：2026-07-22
- 决策人：项目负责人
- 适用范围：`packages/platform-modules/organization` 与组织共享契约
- 依赖决策：ADR-0004、ADR-0006、ADR-0007

## 背景

认证、业务授权、审批、任务和未来数据范围都需要稳定的人员与组织上下文。Keycloak Groups/Roles、企微通讯录和完整 HRM 产品都能表达部分组织信息，但不能同时满足有效期任职、并行兼岗、历史责任查询、厂商隔离和业务中立边界。

历史材料区分账号、员工和 Assignment 的方向是正确的，但账号能力现已归 Keycloak，历史角色枚举、部门类型和业务范围尚未确认，不能原样进入当前模型。

## 决策

1. 自研业务中立的人员与组织核心，不使用 Keycloak、企微通讯录或开源 HRM 的内部模型作为平台组织事实源。
2. 采用以下概念分层；当前只固定语义，不固定表名、字段或 API：

   | 概念 | 语义 |
   |---|---|
   | Authentication Subject | 由 `issuer + sub` 标识的外部认证主体 |
   | Workforce Person | 公司内部自然人的稳定主档案，不等同于客户主档案 |
   | Employment | 人与公司的雇佣、劳务或其他工作关系及其有效区间 |
   | Organization Unit | 公司、部门、团队等业务中立组织节点 |
   | Position | 组织单元中的岗位或职位定义 |
   | Assignment | 某人在有效时间区间内担任某岗位、归属某组织单元的事实 |

3. 认证主体与 Workforce Person 分离。一个人可以暂时没有登录主体，登录被禁用后其组织和历史记录仍然存在。内部人员的一对一有效关联、企微绑定和失效规则后来由 ADR-0018 确认。
4. Employment 与 Assignment 分离。一个人可以存在多段 Employment，也可以拥有多个并行有效 Assignment。
5. 转岗、兼岗、调动和离职通过关闭旧有效区间并创建新事实表达，不覆盖或删除历史。
6. 组织层级和负责人关系必须支持按时间查询。不得只保存无法追溯的“当前上级”或在组织单元中内联一个永久负责人 ID。
7. 岗位与授权角色分离。Position 描述组织职责；授权角色是权限集合。授权原则上关联有效 Assignment 或明确的受控例外，而不是因姓名或岗位文本硬编码。
8. 组织模块不拥有客户归属、销售区域、班级、项目负责人、业绩、绩效、佣金或其他领域关系。
9. 企微、HRM 和其他人员目录通过适配器及正式同步契约接入。领域模块不得直接查询外部目录。
10. 外部同步使用稳定的来源标识和幂等处理，保留来源、同步版本、时间和冲突记录。各字段的最终维护来源在具体集成范围确认时定义。
11. 第一阶段允许人工维护最小组织树、人员、岗位和任职，用于验证登录主体关联、组织上下文和授权，不预建具体业务部门或岗位枚举。

## 核心不变量

- 有效区间必须合法，并统一采用明确的边界语义；具体时间表示在数据设计时确认。
- 组织层级不能形成循环。
- 任职查询不能假设一个人只有一个当前 Assignment。
- 按历史时间查询时必须使用当时有效的组织、岗位和任职事实，不能用当前组织反推过去。
- 认证成功但找不到可用内部人员关联或有效任职时，不自动授予组织权限。
- 创建、调整、关闭和历史纠正必须审计。历史纠正不能静默覆盖原责任事实。
- 外部同步冲突不能以最后写入者无条件覆盖，需要可见、可重试并可人工处理。

## 自研原因

### 不使用 Keycloak 组织模型

Keycloak Groups/Roles 面向认证与粗粒度访问，不能可靠承载多段 Employment、并行 Assignment、组织历史和业务责任时点。把它作为组织主库还会让领域模块被身份产品锁定。

### 不使用企微作为组织主库

企微适合员工通讯录和入口同步，但其组织语义、历史保留和接口生命周期由外部平台决定，也无法覆盖未来所有人员类型。它可以是受控数据来源，不是内部领域接口。

### 不引入完整开源 HRM

HRM 通常包含考勤、薪酬、招聘、假勤等大量当前范围之外的模型。为了少量核心组织事实引入整套产品，会增加数据映射、升级、权限和运维复杂度。

### 自研范围可控

人员、组织单元、岗位、Employment 和 Assignment 是小而稳定的核心模型。通过正式契约与适配器隔离后，可以直接服务授权、任务和审批，又不提前实现完整人力资源系统。

## 公开能力方向

组织模块后续通过契约提供以下能力，而不是暴露数据库：

- 根据认证主体解析内部人员和当前组织上下文。
- 查询某个时间点有效的 Employment、Assignment、组织路径和负责人关系。
- 支持一个人在多个 Assignment 之间选择或组合允许的工作上下文。
- 维护和关闭人员、组织、岗位与任职事实。
- 接收经过批准的外部目录同步命令并报告冲突。
- 发布业务中立的组织变更事件供授权、任务和审计等平台模块消费。

## 失败与一致性

- 主体关联缺失、Employment 失效、组织路径损坏或上下文歧义时失败关闭，并返回稳定错误；单个 Assignment 失效只撤销对应上下文，具体见 ADR-0018。
- 对需要指定当前 Assignment 的操作，调用方不能依赖隐式“第一条任职”。
- 同步、创建和关闭操作需要幂等；重复消息不得生成重复有效关系。
- 组织变更与授权失效之间需要定义事件和缓存版本，具体事务及消息方案另行确认。
- 删除组织节点前必须处理有效子节点和 Assignment；默认使用关闭或停用，不直接物理删除历史事实。

## 影响

- 项目需要自行实现最小组织管理、历史查询、同步适配和不变量测试。
- 授权、审批和任务模块只通过组织公开契约获得上下文，不能共享组织表。
- 未来接入 HRM 或企微时需要字段所有权、冲突和回放策略，但不要求领域模块迁移。
- 具体组织类型、岗位、员工状态、负责人规则和数据范围仍需业务确认。

## 非目标

- 本 ADR 不实现薪酬、考勤、招聘、培训或绩效管理。
- 本 ADR 不定义公司实际部门、岗位名称或汇报关系。
- 本 ADR 不定义客户主档案、客户归属或任何 CRM 对象。
- 本 ADR 不固定数据库表、字段、ORM 或外部同步产品。
