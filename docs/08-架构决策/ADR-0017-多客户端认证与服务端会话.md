# ADR-0017：多客户端认证与服务端会话

- 状态：已接受
- 日期：2026-07-22
- 决策人：项目负责人
- 适用范围：`apps/workbench-web`、`apps/internal-mobile`、`apps/external-portal`、`apps/api` 与认证适配边界
- 依赖决策：ADR-0004、ADR-0005、ADR-0006、ADR-0010、ADR-0015、ADR-0016

## 已知事实

- Keycloak 是唯一身份提供商，业务系统不自建密码、认证 JWT 或 Refresh Token 体系。
- PC Web 已采用 BFF HttpOnly Cookie；内部移动端是 Taro H5，外部端从独立 Taro 应用输出 H5 和微信小程序。
- 项目已采用 Redis，可将其用于有 TTL 的服务端会话和短期认证协调。
- 企微与微信不是 Keycloak 原生标准身份提供商，需要受控适配边界。
- 内部人员主体关联、企微绑定/解绑和 Employment 失效规则后来由 ADR-0018 确认；外部匿名、邀请和长期登录分级后来由 ADR-0019 确认，具体外部主体、首次注册、关联和恢复规则尚未确认。

## 允许的假设

- 内部 H5 需要在企微工作台 WebView 和普通手机浏览器中使用同一套服务端会话语义。
- H5 可以通过同站点网关访问各自 BFF，并使用浏览器 Cookie。
- 微信小程序不能依赖浏览器 Cookie 作为唯一会话机制，需要由 Taro Session Adapter 显式携带不透明会话凭据。
- 提供商登录启用后，最终认证结果仍必须归一为 Keycloak `issuer + sub`。

## 禁止的假设

- 不因为端形态已经确认，就假定外部端必须登录或自动创建任何业务用户；外部访问按 ADR-0019 分级。
- 不根据姓名、手机号、邮箱、前端提交的 `userid`、`openid` 或 `unionid` 自动合并身份。
- 不允许任一客户端持有 Keycloak Access Token、Refresh Token、ID Token、Client Secret 或微信 `session_key`。
- 不允许 BFF 绕过 Keycloak，凭提供商标识直接建立已认证业务主体。
- 不从历史材料继承账号绑定表、`bind_ticket`、外部主体字段或默认授权规则。

## 决策

### 1. Keycloak 继续作为唯一认证权威

所有成功认证最终形成 Keycloak 主体，再由 `auth-context` 转换为内部、与传输无关的主体上下文。企微和微信只提供联合身份入口，不成为第二个认证事实源。

客户端、BFF、领域模块和通知模块不得信任前端声明的外部身份，也不得直接读取 Keycloak、企微或微信的内部存储。

### 2. 客户端与制品使用独立会话边界

- PC Web、内部 H5、外部 H5 和外部微信小程序分别使用受控的 Keycloak Client/会话配置。
- 每个边界拥有独立回调地址、允许来源、会话命名空间、Cookie 或凭据策略、注销和限流配置。
- 外部 H5 与微信小程序即使来自同一 Taro 源码，也不能串用会话或假定相同传输能力。
- 会话必须绑定预期客户端和受众；服务端拒绝把一个客户端的会话用于另一个客户端。

具体 Client ID、域名和回调地址属于环境配置，不硬编码到源码或 ADR。

### 3. 所有 H5 使用 BFF HttpOnly Cookie

PC Web、内部 H5 和外部 H5 均使用 BFF 服务端会话：

- BFF 执行 OIDC Authorization Code 流程及 PKCE、`state`、`nonce` 校验。
- Keycloak Token 只保存在服务端会话边界，浏览器仅持有随机、不透明、可轮换的会话 Cookie。
- 生产 Cookie 使用 `HttpOnly`、`Secure`、Host-only 范围和适合实际回调拓扑的 `SameSite`；优先使用 `__Host-` 前缀。
- 修改状态的请求必须同时校验 `Origin`/`Referer` 和不可预测的 CSRF Token，不能只依赖 `SameSite`。
- 内部 H5 在普通浏览器中可以回退到 Keycloak 标准登录；企微联合登录不可用时不得静默伪造身份。
- 外部 H5 默认不要求长期登录；具体业务按 ADR-0019 选择匿名、邀请或 Keycloak 登录。启用长期登录时仍使用相同的 BFF Cookie 边界。

### 4. 微信小程序只持有项目不透明会话凭据

微信小程序登录采用以下边界：

1. 小程序调用 `wx.login` 获取一次性 `code`，通过 TLS 发送给自己的 BFF 登录端点。
2. 服务端认证适配边界向微信执行 `code2session`；提供商 Secret、响应和 `session_key` 永不返回客户端。
3. 经评审的 Keycloak SPI/认证扩展把已经验证的外部身份解析为 Keycloak 主体。只有 Keycloak 建立可信认证结果后，BFF 才能创建应用会话。
4. BFF 在 Redis 创建有 TTL、可撤销、绑定客户端的服务端会话，并仅向小程序返回高熵、随机、不透明的会话凭据。
5. Taro Session Adapter 从受控存储读取该凭据并放入专用请求头；不得放入 URL、路由参数、日志、埋点或持久化状态快照。

该凭据只是服务端会话句柄，不是自研 JWT、Keycloak Token 或微信 `session_key`。它具有 Bearer 凭据风险，因此必须短期化、轮换、可撤销并限制受众。

### 5. Redis 保存短期会话，不保存永久身份事实

- Redis 保存服务端会话、并发刷新协调、一次性认证状态和短期重放防护数据。
- 会话键采用不可逆摘要或等价防泄漏索引；服务端需要保存的 Keycloak Token 以加密形式存储，密钥来自秘密管理配置。
- 会话具有空闲超时和绝对有效期；具体时长在安全基线中确认，不在代码中散落常量。
- 登录成功、账号关联变化、权限上下文变化和敏感操作后轮换会话标识。
- Keycloak、人员、任职、业务授权和外部身份关联仍是持久事实，不能只存在 Redis。
- Redis 不可用、会话数据缺失、解密失败或刷新失败时必须失败关闭。

### 6. 企微和微信适配采用开源核心加自研薄适配

| 能力 | 选择 | 原因 |
|---|---|---|
| 身份、OIDC、Token 与认证会话 | 开源 Keycloak | 安全生命周期复杂，不自研认证中心 |
| 标准 OIDC、Cookie、CSRF、加密和随机数 | 成熟开源库 | 不自研协议和密码学 |
| 服务端会话存储 | 已选开源 Redis | 支持 TTL、撤销、水平扩展和短期协调 |
| BFF 会话编排与 Taro Session Adapter | 自研薄层 | 与应用、网关、Cookie、受众和错误语义直接相关 |
| 企微/微信协议适配 | 自研并维护薄 Keycloak SPI/适配器 | 非标准提供商且处于高风险认证边界，需要固定版本、可审计和可测试 |

不修改 Keycloak 源码。社区企微/微信插件只能作为调研输入；只有许可证、维护状态、代码安全、Keycloak 版本兼容、失败行为和升级测试全部通过评审后，才可替代自研适配器。

在锁定 Keycloak 版本和认证扩展点前先做兼容性验证，明确浏览器联合登录与小程序 `code2session` 分别使用的 SPI 类型。不得用未经验证的自定义 Grant 或管理 API 模拟用户登录。

### 7. 账号关联和恢复按主体类型独立决策

- 提供商身份已经验证但尚未关联 Keycloak 主体时，不创建正常应用会话，也不授予人员、组织、角色或数据权限。
- 如需跨页面继续关联，只能使用短时、一次性、受众绑定的服务端认证事务状态；它不是业务账号或长期登录凭据。
- 同一提供商身份发生重复关联冲突时失败关闭并进入安全审计，不自动覆盖。
- 内部人员的首次关联、企微绑定/解绑和 Employment 失效执行 ADR-0018。ADR-0019 不要求匿名或邀请访问者建立账号；只有确认需要长期登录的外部主体，才另行定义首次创建、关联、解绑、换绑、账号恢复和管理员代操作规则。

### 8. 注销、失效、重放与幂等

- 注销必须撤销本地会话，并在适用时调用 Keycloak 标准注销；客户端立即清理本地句柄。
- 人员/任职失效、Keycloak 账号禁用和安全强退需要定义传播路径，任何缓存都不能让失效主体长期保持访问。
- OAuth 回调、`wx.login` code 和会话轮换操作按一次性语义处理；重复请求不得创建多条有效会话或重复关联。
- H5 重点防范 CSRF、会话固定和 Cookie 范围错误；微信小程序重点防范凭据泄漏、重放、错误受众和重复提交。
- 所有受保护请求仍由服务端执行功能权限、数据范围和对象级授权；会话存在不等于具有业务权限。

## 认证与会话矩阵

| 制品 | 可用认证入口 | 客户端凭据 | 主要防护 |
|---|---|---|---|
| PC Web | Keycloak 标准登录 | HttpOnly Cookie | OIDC 校验、CSRF、会话固定防护 |
| 内部 H5 | Keycloak 标准登录；启用后可走企微联合登录 | 独立 HttpOnly Cookie | WebView 回调、CSRF、客户端隔离 |
| 外部 H5 | 按外部身份规则启用 Keycloak/微信联合登录 | 独立 HttpOnly Cookie | 限流、防枚举、CSRF、最小错误披露 |
| 微信小程序 | 启用后使用 `wx.login` + 服务端 `code2session` + Keycloak 扩展 | 不透明会话凭据 | 短期轮换、撤销、重放与受众校验 |

## 可观测性与审计

- 登录开始、回调、提供商交换、会话创建、刷新、轮换、注销、冲突和失败记录结构化结果、客户端、提供商、错误类别与 Trace ID。
- 日志、指标和 Trace 禁止记录 Cookie、会话凭据、Token、授权码、`session_key`、Client Secret 或不必要的外部标识明文。
- 指标至少覆盖登录结果、提供商延迟/错误、会话创建/刷新/撤销、CSRF 拒绝、重放拒绝和 Redis/Keycloak 依赖健康。
- Keycloak、Redis 或提供商异常需要可区分的健康与告警，但客户端只获得稳定、最小披露的错误语义。

## 测试要求

- 契约测试覆盖客户端/受众隔离、未登录、会话过期、凭据串用和错误最小披露。
- H5 集成测试覆盖 OIDC 回调、Cookie 属性、CSRF、轮换、刷新竞争、注销和 WebView 返回。
- 微信小程序测试覆盖一次性 code、伪造提供商标识、`code2session` 超时/失败、重复请求、会话重放、轮换和清理。
- Keycloak 适配器测试覆盖首次未关联、已有身份、关联冲突、提供商故障和 Keycloak 升级兼容。
- 测试和 Mock 不得通过生产可达开关绕过 Keycloak 或构造管理员主体。

## 已考虑的方案

### H5 和小程序直接持有 Keycloak Token

实现直接，但把 Token 刷新、注销和泄漏风险带入 Taro 运行时与客户端存储，因此不采用。

### BFF 直接信任 `openid`/`userid` 并签发自有 JWT

能绕开 Keycloak 适配成本，但会形成第二认证中心并信任可伪造输入，因此不采用。

### 直接采用社区 Keycloak 微信插件

接入可能较快，但认证核心的维护、版本兼容和安全质量不能仅由依赖名称保证。先评审、再决定是否替代自研薄适配，不作为默认方案。

### H5 使用 Cookie，小程序使用不透明服务端会话

符合各运行环境的传输能力，同时保持 Keycloak Token 只在服务端并支持统一撤销，因此采用。

## 影响

- `apps/api` 承担多客户端 BFF 会话编排，但不拥有身份事实或业务授权。
- 需要维护彼此隔离的会话配置、Redis 命名空间、Keycloak Client 和端到端测试。
- 微信小程序认证需要锁定 Keycloak 扩展方式并进行真实微信环境验证，不能只靠浏览器 Mock。
- 内部人员关联执行 ADR-0018；外部访问执行 ADR-0019。具体外部账号生命周期未确认前，认证适配只能失败关闭，不得自行补全业务身份。

## 待后续决策

- 首个外部业务场景使用匿名、邀请还是长期登录，以及面向何种外部主体。
- 外部主体首次关联、解绑、换绑、账号恢复和管理员代操作规则。
- 内部 Keycloak 用户禁用、重新启用和全部 Employment 失效后的公司级账号策略。
- 会话空闲/绝对有效期、同时在线设备数、强制失效传播目标和敏感操作重新认证范围。
- Keycloak 固定版本、企微/微信具体 SPI 类型、提供商应用配置、域名和测试账号。
- 小程序本地会话凭据清理、设备退出和风险事件后的恢复交互。

## 非目标

- 本 ADR 不定义 CRM 用户、客户、合作方或其他外部主体模型。
- 本 ADR 不确认企微/微信提供商配置已经可用，也不代表第三方登录已经实施。
- 本 ADR 不定义业务角色、权限码、组织关系、数据范围或登录后的业务页面。
- 本 ADR 不创建账号关联表、认证 HTTP 端点或 Keycloak SPI 实现。
