# ADR-0022：第一阶段轻量可观测性基线

- 状态：已接受
- 日期：2026-07-23
- 决策人：项目负责人
- 适用范围：所有 `apps/`、`packages/observability`、`deploy/observability`、运行组件和客户端错误报告
- 依赖决策：ADR-0002、ADR-0003、ADR-0010、ADR-0011、ADR-0017、ADR-0020、ADR-0021

## 已知事实

- 项目负责人确认沿用历史原方案：Pino 结构化日志、Sentry、腾讯云云监控和简单外部可用性告警。
- 第一阶段生产使用两台云服务器和自托管 Docker Compose，运维资源有限。
- PostgreSQL、Redis、RabbitMQ、Keycloak、Flowable、Nginx 和 ClamAV 都需要基本健康、容量和故障信号。
- 审计记录、业务事实、应用日志、错误事件、指标和 Trace 是不同数据，不可相互替代。
- 当前尚未确认 Sentry 账号区域、合同与数据出境条件、告警接收人、数据保留期、采样率和正式 SLA。

## 允许的假设

- 第一阶段可以用托管错误追踪和云主机监控降低自托管成本。
- 应用可以使用 OpenTelemetry/W3C 标准传播 Trace Context，同时将第一阶段的采样 Trace 发送到 Sentry，而不部署通用 Collector。
- 未形成集中日志平台前，受控运维人员可以在两台服务器分别检索轮转后的 JSON 日志。

## 禁止的假设

- 不把 Sentry 事件、Pino 日志或云监控指标作为业务事实或合规审计记录。
- 不允许为了排错上传请求/响应正文、Cookie、Token、Session、密码、Client Secret、个人敏感信息、完整客户资料或供应商原始载荷。
- 不把客户端提供的 Request ID、Trace ID、用户标识或错误文本直接视为可信数据。
- 不把“接入 Sentry”表述为微信小程序 SDK 已兼容、数据出境已批准或所有异常都能被捕获。
- 不因为保留 OpenTelemetry 接口就部署未确认的 Collector、Prometheus、Grafana、Loki、ELK 或其他观测集群。

## 决策

### 1. 使用轻量四层可观测组合

| 层次 | 选择 | 自研、开源或托管 | 原因 |
|---|---|---|---|
| 应用结构化日志 | Pino，NestJS 使用兼容 Pino 集成 | 开源库 + 项目自研字段、脱敏和中间件 | Node 性能成熟，JSON 输出便于 AI 和运维检索，不自研日志框架 |
| 错误与采样性能追踪 | Sentry 官方 SDK 与托管 Sentry | 托管服务 + 薄项目 Adapter | 避免在两台服务器自托管 Sentry 所需的数据库、队列、存储和升级体系 |
| 主机与基础可用性 | 腾讯云云监控、Agent 和站点/端口探测 | 腾讯云托管服务 | 与 CVM 同平台，第一阶段无需自建 Prometheus、Alertmanager 和 Grafana |
| Trace 标准与传播 | OpenTelemetry API/语义约定、W3C Trace Context | 开源标准 + 项目自研统一初始化 | 避免业务模块绑定 Sentry，保留未来更换后端的能力 |

第一阶段不部署 OpenTelemetry Collector、Prometheus、Grafana、Loki、ELK/Elastic Stack 或自托管 Sentry。Sentry 的托管区域、网络可达性、合同、保留和数据跨境必须在生产启用前完成安全评审。

### 2. `packages/observability` 是薄适配层

项目自研的 `packages/observability` 负责：

- Pino 初始化、稳定字段、日志级别和按环境配置。
- 请求、消息、Job、Webhook 和外部调用的关联上下文。
- OpenTelemetry/W3C Trace Context 的提取、校验、生成和传播。
- Sentry 初始化、Release/Environment 标记、采样、脱敏和关闭刷新。
- 统一指标名称方向、健康检查约定和测试辅助。
- 前后端可替换的 `ErrorReporter`/Telemetry 边界；具体公开 API 在实施前评审。

它不提供业务审计、用户行为分析、业务指标口径、任意日志搜索服务或自研 APM 后端。领域模块只能记录稳定业务引用和结果类别，不能导入 Sentry SDK 或依赖 Pino 内部对象。

### 3. 结构化日志字段与边界

服务端日志至少支持以下稳定上下文方向：

- `timestamp`、`level`、`service`、`environment`、`version`、`instance_id`。
- `trace_id`、`span_id`、`request_id`，异步链路增加 `message_id`、`correlation_id`、`causation_id`、消费者和尝试编号。
- HTTP 方法、路由模板、状态类别、耗时和稳定错误码；不记录原始 Query、完整 URL 或请求正文。
- 模块、操作名称、结果类别和必要的内部资源引用；不记录完整业务对象。

日志输出到 stdout/stderr，由 Docker 日志驱动限制单文件大小、轮转数量和磁盘上限。应用不得自行写无限增长的宿主机日志文件。

以下内容默认拒绝进入日志、Sentry Breadcrumb、Tag、Context、Extra、Trace Attribute 和指标 Label：

- Authorization/Cookie/Set-Cookie、Keycloak Token、会话句柄、微信 `session_key`、验证码和各类 Secret。
- 密码、手机号、身份证号、邮箱、地址、客户沟通正文、表单提交正文、附件内容和支付凭证。
- 未脱敏 Webhook、供应商请求/响应、数据库行、SQL 参数和消息完整载荷。
- 高基数或不受控文本，如完整 URL、异常供应商返回、用户输入和动态对象序列化结果。

确有诊断需要时只记录稳定内部引用、长度、摘要、字段存在性或受控枚举。新增字段必须经过日志数据分类评审。

### 4. Sentry 使用边界

- 服务端 API、Worker、PC Web 和支持官方/已验证 SDK 的 H5 制品接入 Sentry；每个制品使用独立 Release 和环境标签。
- 微信小程序必须先完成 SDK/Taro 兼容、包体、Source Map、网络域名和脱敏测试；未验证前不伪造已接入状态。
- 默认关闭“发送默认个人信息”、请求正文、Session Replay、附件和任意控制台对象采集。
- 使用 `beforeSend` 或等价处理实施允许列表与二次清洗；未知字段默认丢弃。
- Source Map 只在 CI 使用受限 Token 上传到对应 Release，不公开部署源文件，也不把上传 Token 写入前端或仓库。
- 性能 Trace 按环境和操作配置采样；认证、外部提交、文件和其他敏感链路可以进一步降低采样或禁止正文/Breadcrumb。
- Sentry 不承载审计、业务成功率、消息最终状态、数据库备份成功或 SLA 计算。
- Sentry 不可用不得阻断业务请求；SDK 发送必须有短超时、有限队列和进程退出刷新上限。

### 5. Trace 与异步链路

- 入站 HTTP 从受控 W3C `traceparent` 提取父上下文；不合法或不受信任的字段丢弃并生成新 Trace。
- BFF、API、Outbox、RabbitMQ、Worker、Workflow Facade、文件处理和 Provider Adapter 传播 Trace/Correlation Context。
- 领域事件保持传输中立；Trace 字段属于信封/元数据，不进入领域业务载荷。
- 重试创建新 Span/Attempt 并关联原操作，不能覆盖历史失败；消息重投、外部调用重试和业务补偿分别标记。
- Trace 丢失不能改变幂等、授权、事务、重试或业务结果。

具体信封字段在事件和 Job 契约评审时版本化，本 ADR 不直接创建未经确认的 Schema。

### 6. 健康检查与外部可用性

- 每个运行组件区分进程存活、接流量就绪和受控深度诊断。
- 存活检查不因普通下游故障重启健康进程；就绪检查反映当前实例能否安全承接其职责。
- API、Worker、Keycloak、Flowable、PostgreSQL、Redis、RabbitMQ、Nginx、ClamAV、磁盘和备份分别定义健康信号。
- 公网可用性探测从两台服务器故障域之外访问最小无敏感信息端点和批准的关键入口。
- 健康响应不得返回版本漏洞细节、连接字符串、主机路径、队列名称、租户、账号或 Secret。
- 深度诊断和组件管理端点只允许受控运维网络与授权人员访问。

健康端点的 HTTP 契约和依赖降级规则在实施任务中先评审，再实现。

### 7. 腾讯云云监控与告警

第一阶段至少覆盖：

- CVM CPU、内存、负载、磁盘空间/IO、网络、时间同步和实例不可达。
- Docker 容器退出、反复重启、健康失败和日志磁盘接近上限。
- PostgreSQL 连接、查询/事务异常、锁/死锁、磁盘和备份/WAL 失败。
- Redis 内存、连接、淘汰、持久化失败；RabbitMQ 连接、未确认消息、积压、死信、磁盘/内存水位。
- Keycloak/Flowable 登录或健康失败，Nginx 5xx/上游失败，ClamAV 病毒库过期或扫描服务不可用。
- Sentry 新回归、错误率突增和关键 Release 部署异常。
- 外部探测连续失败、TLS 证书临期和域名解析异常。

每条生产告警必须有严重级别、连续窗口或抑制规则、接收 Owner、升级路径和 Runbook 链接。不得对每个单次错误直接群发告警，也不得只发送到无人负责的公共群。

阈值、窗口和接收渠道在获得容量基线与值班安排后确定；当前不虚构数值。

### 8. 审计、业务指标与观测数据分离

- 审计模块保存“谁在何时因何原因对什么资源做了什么及结果”，使用追加式耐久记录。
- Pino/Sentry 记录技术执行与异常，可丢弃、采样和按保留策略删除，不能证明业务动作发生。
- 腾讯云云监控记录运行资源与可用性，不计算销售、订单、客户或员工经营指标。
- 业务指标必须由未来拥有模块的正式事实和口径生成，不能从日志关键词或 Sentry 事件统计。
- `trace_id` 可以连接审计、日志和错误事件，但这些数据仍保持各自权限、保留和事实所有权。

## 安全与隐私

- Sentry DSN、Org/Project、采样率和环境属于部署配置；Sentry 上传 Token、Webhook Secret 和管理凭据只使用秘密引用。
- 生产启用 Sentry 前必须完成数据处理协议、地域/跨境、子处理者、保留、删除、账号权限和退出导出评审。
- Sentry、云监控和服务器日志使用独立最小权限账号，生产查询和规则修改纳入审计。
- 前端错误不能包含其他用户数据；服务端异常返回公共错误码和安全 Trace 引用，不把 Stack 或内部路径返回客户端。
- 日志与错误事件定义保留和删除策略；离开项目的人员及时回收访问权限。

## 测试与验收

- 单元测试覆盖字段允许列表、递归脱敏、异常序列化、头部清洗和高基数限制。
- 集成测试验证 HTTP、Outbox、RabbitMQ、Worker 和 Adapter 的 Trace/Correlation 传播。
- 故障测试验证 Sentry、DNS或云监控不可用不阻断业务，日志磁盘限制不会耗尽系统盘。
- 客户端测试检查生产构建不包含 Source Map Token、Secret、内部 DSN 管理凭据或敏感 Breadcrumb。
- 预发布产生受控测试异常和告警，验证 Release、环境、Owner、去重、恢复通知和 Runbook。
- 通过自动扫描和人工抽样确认日志/Sentry 中没有 Token、Cookie、手机号、客户正文或完整载荷。

## 已考虑的方案

### 自托管 Prometheus、Grafana、Loki 和 Alertmanager

功能完整且数据可控，但会继续占用两台服务器资源并增加存储、升级、备份和值班工作，第一阶段不采用。

### 自托管 Sentry

避免外部数据传输，但依赖组件和资源明显超出当前两服务器轻量部署目标，第一阶段不采用。

### 只有文本日志

成本最低，但缺少跨请求关联、客户端异常聚合、Release 回归和外部可用性，因此不采用。

### Pino + 托管 Sentry + 腾讯云云监控

覆盖日志、错误、采样 Trace、主机指标和外部可用性，同时保持运维负担较低，因此采用。

## 影响与已接受风险

- 两台服务器上的完整 JSON 日志第一阶段没有集中检索，主机损坏可能丢失未外送日志；Sentry 和云监控不等于日志备份。
- Sentry SaaS 存在网络可达性、费用、数据地域与供应商依赖，需要生产启用门禁和退出方案。
- 没有 Prometheus/Grafana 意味着复杂指标探索和跨组件容量分析能力有限。
- 统一 OpenTelemetry 边界降低未来接入 Collector 或其他后端的迁移成本，但不会自动生成正确埋点。

## 升级触发条件

满足任一条件时重新评审集中日志或完整指标/Trace 平台：

- 两台服务器日志检索已显著延长故障定位，或出现需要跨实例关联但无法完成的事故。
- 需要基于细粒度 SLI/SLO、队列延迟、数据库性能或业务关键路径进行持续容量管理。
- Sentry 网络、成本、合规或保留能力无法满足要求。
- 服务/实例数量、事件量或值班团队规模明显增加。
- 法规或客户合同要求观测数据位于指定地域或自有环境。

## 待后续确认

- Sentry 账号区域、套餐、项目划分、数据处理协议、保留和 Source Map 策略。
- 腾讯云云监控 Agent、外部探测、告警接收与升级渠道。
- 日志保留、Sentry 采样率、告警阈值、静默窗口和 Owner。
- 微信小程序错误上报的兼容方案。
- 首次容量基线和关键服务的 SLI/SLO。

## 非目标

- 本 ADR 不定义 CRM 业务指标、绩效指标或 SLA 数值。
- 本 ADR 不创建可观测平台业务模块或让领域代码依赖 Sentry。
- 本 ADR 不批准向境外服务发送个人信息或客户业务内容。
- 本 ADR 不生成不存在的告警账号、Webhook、DSN、Token 或生产配置。
