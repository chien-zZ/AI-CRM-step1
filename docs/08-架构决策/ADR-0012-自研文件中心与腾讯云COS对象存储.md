# ADR-0012：自研文件中心与腾讯云 COS 对象存储

- 状态：已接受
- 日期：2026-07-22
- 决策人：项目负责人
- 适用范围：`file-center`、文件上传下载、对象存储、恶意文件扫描和业务文件引用
- 依赖决策：ADR-0003、ADR-0007、ADR-0010、ADR-0011

## 已知事实

- CRM 与未来公司工作台需要共享附件能力，但具体合同、凭证、证据等业务文件类型和规则尚未确认。
- 文件访问必须服从业务授权和数据范围，不能因获得对象存储地址而绕过应用权限。
- API 与 Worker 已分离，RabbitMQ、Outbox/Inbox 和 PostgreSQL 模块数据所有权已经确认。
- 项目负责人确认自研文件中心，生产使用腾讯云 COS，本地使用文件系统适配器，并使用 ClamAV 扫描恶意文件。

## 允许的假设

- 第一阶段主要处理用户上传的业务附件，不建设在线协作文档或企业网盘。
- 浏览器能够使用短时预签名凭证直传对象存储。
- 文件扫描、元数据补全、清理和对账由 `apps/worker` 异步执行。

## 禁止的假设

- 不从历史材料推断具体附件类型、大小限制、扩展名白名单、保存期限、可见角色或业务必填规则。
- 不把 COS Object Key、ETag 或 URL 当成业务文件标识。
- 不把客户端声明的文件名、MIME、大小、摘要或“上传成功”作为可信事实。
- 不默认 ETag 等于文件内容哈希，特别是分片上传场景。
- 不在本 ADR 中决定 COS 地域、Bucket、存储级别、CDN、KMS、归档周期、版本或 SDK 版本。

## 决策

### 1. 文件中心自研

`packages/platform-modules/file-center` 自研业务中立的文件控制面，负责：

- 文件元数据、上传会话、不可变内容版本和处理状态。
- 文件与业务资源引用之间的受控关联。
- 文件分类、授权下载、审计、保留与删除编排。
- COS 与本地文件系统适配器、ClamAV 适配器及失败对账。

选择自研的原因是业务对象引用、组织和数据范围授权、审计、版本及保留规则属于本项目语义。通用网盘或文档管理产品通常自带用户、目录和权限模型，直接接入会形成第二套权限与业务对象体系。

自研不包括对象存储、杀毒引擎、分片协议或通用文件系统。文件中心只实现稳定控制面和厂商适配边界。

### 2. 生产使用腾讯云 COS 托管服务

文件二进制存放在私有腾讯云 COS Bucket，不写入 PostgreSQL。COS 是托管云服务，不是本项目自研或开源组件；项目通过自研 `StorageAdapter` 和官方支持的 SDK/协议接入。

选择 COS 的原因是对象耐久性、容量扩展、分片上传、服务端加密、生命周期和可用性保障属于成熟基础设施能力。自建对象存储会增加磁盘、复制、修复、容量和灾难恢复负担，不是第一阶段差异化能力。

`StorageAdapter` 只抽象项目确实需要的上传、检查、读取、删除和签名能力，不追求覆盖所有云厂商功能。领域模块、HTTP 契约和 `platform-sdk` 不出现 COS Bucket、Object Key、凭据或 SDK 类型。

### 3. 本地文件系统适配器仅用于开发和测试

本地开发默认使用文件系统适配器，文件只能写入受控的项目数据目录。路径由服务端生成并规范化，禁止使用客户端文件名拼接路径，必须防止目录穿越、符号链接逃逸和越权读取。

本地适配器不是生产方案，也不能证明 COS 预签名、CORS、分片上传和权限配置正确。CI 需要运行统一的 StorageAdapter 契约测试；预发布或专用集成环境必须连接真实测试 Bucket 验证 COS 路径。

### 4. 使用开源 ClamAV，不自研病毒引擎

ClamAV 负责恶意文件扫描，文件中心负责扫描编排、状态、隔离、重试和审计。选择开源 ClamAV 的原因是恶意代码特征库、格式解析和持续更新需要专门安全产品维护，自研不可接受。

ClamAV 必须经适配器调用，Worker 不把其返回模型泄露给业务模块。扫描服务不可用、特征库过期、扫描超时、文件无法解析或加密压缩包无法检查时，文件保持不可用或进入隔离状态，不能默认放行。

病毒扫描只是纵深防御的一层，不能替代类型识别、大小限制、权限、私有 Bucket、内容安全策略和下载审计。

### 5. 上传采用受控会话与预签名直传

标准上传流程为：

1. 客户端向文件中心申请上传会话，提交预期用途、显示文件名、声明类型、大小等待校验信息。
2. 文件中心先做服务端授权、策略校验和配额检查，再生成不可猜测 Object Key 和短时、限用途的上传凭证。
3. 客户端直接上传 COS。永久凭据不得进入浏览器，上传凭证只能用于指定 Bucket、Object Key、方法、有效期和允许的请求约束。
4. 客户端调用幂等完成接口。文件中心通过可信 COS API 检查对象是否存在，并核对实际大小、可用校验值及元数据；不能只信客户端回报。
5. 文件进入待校验/待扫描状态，由 Worker 使用 RabbitMQ 任务执行 MIME 探测、策略校验和 ClamAV 扫描。
6. 只有校验与扫描成功的文件版本才能进入可用状态并建立正式业务关联。

大文件可以采用受控分片上传，但分片会话、过期清理和完成确认仍归文件中心管理。API 默认不代理全部文件流量；只有高敏下载、兼容性或安全策略明确要求时才使用服务端代理。

### 6. 下载必须逐次授权

- COS Bucket 和对象保持私有，不提供永久公开 URL，也不把 Object Key 返回为业务契约。
- 下载请求先通过文件中心，使用当前主体、组织上下文、稳定业务资源引用和操作类型执行服务端授权。
- 授权成功后签发短时、最小权限下载地址；高敏文件可强制服务端代理、附加水印或更严格审计，具体分类策略后续确认。
- 文件名通过安全的 `Content-Disposition` 返回，必须清理控制字符和注入字符。
- 已隔离、删除中、扫描未完成、引用失效或来源业务对象不可见时拒绝下载。

拥有一个曾经有效的 URL 不代表永久有权访问。签名有效期应尽量短；权限立即撤销要求高的类别不能只依赖已经签出的 URL，必须使用代理或额外控制。

### 7. 文件版本与业务关联

- 每个已完成的二进制对象不可原地覆盖。替换文件会创建新的内容版本和新的 Object Key。
- 业务模块只保存或交换稳定的 `file_id`/版本化 `FileReference`，不保存存储地址。
- 文件中心拥有业务资源关联记录，关联使用传输中立的资源类型、资源标识和关系语义，不建立跨模块数据库外键。
- 创建、替换、解除关联和下载必须通过公开接口，并由业务拥有模块或授权核心裁决权限。
- 一个物理内容是否允许复用于多个业务引用属于后续策略；不能通过向用户暴露“哈希已存在”泄露其他对象的文件存在性。

### 8. 生命周期、删除与对账

- 上传会话、未完成分片和无关联临时对象必须有过期清理机制。
- 删除先改变 PostgreSQL 中的控制状态，再异步删除 COS 对象；操作必须幂等并能从部分失败恢复。
- 数据库元数据与 COS 对象不假设分布式事务。创建、完成、扫描、关联和删除均通过可恢复状态、Outbox/Inbox、重试和定期对账收敛。
- 定期检查“数据库有记录但对象缺失”“对象存在但上传会话过期”“删除状态与实际对象不一致”等漂移。
- 业务删除不自动等于物理删除。保留、归档、法务冻结和彻底销毁策略在数据治理确认后定义。

## 数据、安全与审计

- PostgreSQL 保存文件与版本标识、原始显示名、可信探测类型、实际大小、校验信息、存储适配器引用、状态、分类、上传者、时间和业务关联；具体字段等待契约与迁移评审。
- Object Key 使用服务端生成的不可猜测值，不包含原文件名、手机号、客户名或其他敏感业务信息。
- COS 使用服务端加密、私有访问、受限 CORS、最小权限子账号和独立环境 Bucket；是否使用 KMS 客户管理密钥按数据分类另行确认。
- 上传凭证、下载签名和存储凭据不得写入日志、事件或审计详情。
- 上传申请、完成、扫描结果、隔离、关联、下载、删除、恢复和管理操作保留主体、资源、原因、结果、IP/终端及 Trace 关联；具体审计保留策略后续确认。

## 失败与幂等

- 上传会话创建成功但签名失败：保留可重试会话或安全过期，不创建可用文件。
- COS 上传成功但客户端未完成确认：过期扫描发现对象后按策略恢复确认或清理，不能永久泄漏对象。
- 完成接口重复调用：返回同一个稳定结果，不创建重复文件版本。
- 扫描任务重复、超时或 Worker 崩溃：通过确定性 Job ID、Inbox 和状态检查安全重试。
- 数据库提交成功但 COS 操作失败：记录待协调状态并重试；不能伪造对象已存在或已删除。
- 下载签名生成失败：返回可重试错误并保留审计，不回退为公开访问。

## 可观测性

- 指标至少覆盖上传会话数量与过期、完成延迟、校验失败、扫描积压/耗时/失败、隔离数量、签名失败、下载拒绝、对象删除失败和元数据漂移。
- 健康检查分别报告 PostgreSQL、RabbitMQ、COS 和 ClamAV 依赖状态；依赖不可用时仅开放仍能安全完成的能力。
- 日志使用 `file_id`、版本 ID、上传会话 ID、Job ID 和 Trace ID 关联，不记录签名 URL、凭据或不必要的原始文件名。

## 测试要求

- StorageAdapter 契约测试在本地文件系统和 COS 测试 Bucket 上运行相同用例。
- 集成测试覆盖预签名约束、重复完成、伪造 Object Key、大小/MIME 不符、扫描成功/失败/超时、隔离、授权下载和删除对账。
- 安全测试覆盖目录穿越、文件名响应头注入、双扩展名、内容与扩展不符、压缩包风险、过期签名和跨资源越权。
- 故障测试覆盖数据库、RabbitMQ、COS、ClamAV 分别不可用以及恢复后的积压处理。
- 第一阶段使用业务中立测试资源，不创建合同、凭证或其他未确认 CRM 文件类型。

## 已考虑的方案

### 各业务模块直接接入 COS

初期调用简单，但会重复签名、权限、扫描、版本、审计和清理逻辑，并把 Object Key 传播为业务数据，因此不采用。

### PostgreSQL 保存二进制

事务看似统一，但会显著放大数据库、备份、复制和查询负担，也不适合大文件与直传，因此不采用。

### 自建 MinIO 或其他对象存储

可以获得 S3 兼容和本地一致环境，但项目必须承担容量、复制、磁盘修复、升级和灾备。第一阶段优先降低运维风险，生产不采用；未来只有在合规、成本或云迁移有明确证据时重新评估。

### 接入完整网盘或文档管理系统

可获得目录、共享和协作功能，但会引入第二套身份、权限和业务对象模型。当前需要的是嵌入工作流的文件能力，不是独立网盘，因此不采用。

### 自研文件中心 + COS + ClamAV

自研项目特有控制面，复用托管对象存储和开源安全扫描能力，职责与成本边界最清晰，因此采用。

## 影响

- 生产增加 COS 配置、费用、网络依赖、监控和厂商适配维护。
- Worker 增加文件验证、扫描、清理与对账负载，需要独立并发和资源限制。
- 本地文件系统不能完整模拟 COS，预发布必须承担真实链路验证。
- 未来更换对象存储时需要实现并通过 StorageAdapter 契约测试，但业务契约和 `file_id` 不变。

## 非目标

- 本 ADR 不定义任何 CRM 附件类型、必填规则、可见角色或保存年限。
- 本 ADR 不建设在线编辑、多人协作、知识库、OCR、电子签章、媒体转码或全文内容搜索。
- 本 ADR 不允许文件中心决定领域对象是否存在或处于何种业务状态。
- 本 ADR 不保证本地文件系统与 COS 的所有实现细节完全一致。
