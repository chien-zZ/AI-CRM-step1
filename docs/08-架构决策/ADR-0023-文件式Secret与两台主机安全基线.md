# ADR-0023：文件式 Secret 与两台主机安全基线

- 状态：已接受
- 日期：2026-07-23
- 决策人：项目负责人
- 适用范围：`packages/config`、`deploy/secrets`、Docker Compose、两台生产 CVM、备份与运维访问
- 依赖决策：ADR-0004、ADR-0005、ADR-0011、ADR-0012、ADR-0013、ADR-0017、ADR-0020、ADR-0021、ADR-0022

## 已知事实

- 项目负责人确认采用调整后的历史原方案：不部署 HashiCorp Vault，不使用腾讯云 Secrets Manager 或其他集中 Secret 产品。
- 生产运行于两台腾讯云 Ubuntu CVM，每台运行独立 Docker Compose Project。
- 当前业务配置中心已明确禁止保存密码、Token、连接凭据、证书私钥和其他 Secret。
- 项目需要管理数据库、Redis、RabbitMQ、Keycloak、会话加密、COS、Sentry、TLS、备份加密及未来供应商凭据。
- 当前尚未确认正式运维 Owner、轮换周期、应急联系人、SSH 入口、证书签发方式和具体 Secret 清单。

## 允许的假设

- 第一阶段可以由少量受权运维人员通过受控 SSH/SFTP 在两台服务器分别分发 Secret 文件。
- Docker Compose 的 `secrets`/只读文件挂载以及应用 `*_FILE` 配置可以避免把多数 Secret 放入 Compose 字面值和容器元数据。
- 可以使用成熟系统工具生成随机值、设置 Linux 权限并加密异地应急副本，不自研密码学算法。

## 禁止的假设

- 不把普通 `.env`、业务配置中心、数据库表、Wiki、聊天记录、工单附件或 CI 变量列表当成长期 Secret 保险库。
- 不在 Git 中保存明文或加密后的生产 Secret；“已加密”不等于可以进入仓库。
- 不把 Secret 明文写入 Compose YAML、Dockerfile、镜像层、命令行参数、Shell 历史、日志、Sentry、Trace、前端制品或 Source Map。
- 不允许所有服务和环境共用一个数据库账号、COS 密钥、Cookie 密钥或供应商账号。
- 不因为文件权限存在就宣称具备逐次读取审计、自动租约、集中撤销或硬件密钥保护。
- 不从历史材料推断客户字段需要字段级加密；数据分类和字段加密范围必须另行确认。

## 决策

### 1. 使用主机受限文件与 Docker Compose Secret 挂载

生产 Secret 的标准链路为：

```text
受权运维生成或取得 Secret
  → 通过受控 SSH/SFTP 分别写入目标主机
  → root 拥有的受限 Secret 文件
  → Docker Compose secrets / 只读单文件挂载
  → 容器内 /run/secrets/<name>
  → packages/config 或第三方镜像的 *_FILE 读取能力
```

- 主机建议统一使用 `/etc/ai-crm/secrets/<environment>/<service>/<secret-name>` 作为生产 Secret 根目录；最终路径在部署实施中固定。
- Secret 目录默认仅 root 可进入；文件默认 `0400`，确需专用部署组读取时最多放宽到受控的 `0440`，不得使用全局可读权限。
- Compose 文件只声明 Secret 名称、宿主机文件路径和目标挂载，不包含明文值。
- 容器只挂载自身需要的 Secret，使用只读单文件挂载，不把整个 Secret 根目录交给任一容器。
- 项目应用优先通过 `*_FILE` 配置读取 Secret；非秘密配置继续使用类型化环境变量。
- 第三方镜像不支持文件读取时，必须经过例外评审，使用最小启动包装在进程内读取；不得把 Secret 回写到镜像、Compose、日志或可复用配置文件。
- Secret 缺失、不可读、为空、格式不合法或版本不兼容时，服务启动失败关闭，不回退到默认密码或开发值。

### 2. 自研、开源与托管边界

| 能力 | 选择 | 原因 |
|---|---|---|
| Secret 引用、`*_FILE` 加载、类型/格式校验和安全错误 | 项目自研薄 `packages/config` 边界 | 需要与项目配置、服务启动和错误语义一致，不实现保险库或密码学 |
| 单机 Secret 注入 | Docker Compose `secrets` 与 Linux 只读挂载 | 使用现有开源运行能力，避免明文进入 Compose 环境值 |
| 文件所有权、权限、SSH/SFTP、sudo 和系统审计 | Ubuntu/OpenSSH/Linux 标准能力 | 两台主机规模下可控，不新增中心服务 |
| 随机值、密钥与证书工具 | 操作系统 CSPRNG、OpenSSL/官方工具 | 不自研随机数、加密算法或证书格式 |
| 异地应急 Secret 包加密 | 开源 `age` 或经安全评审的等价标准工具 | 使用离线公钥加密，避免自研加密；私钥不放生产主机或 COS |
| Secret 存储产品 | 不使用 Vault、腾讯云 Secrets Manager 或其他托管/自建保险库 | 项目负责人选择调整后的原方案，接受人工分发和轮换成本 |

### 3. Secret 分类和最小权限

至少分别管理以下类别，不保存真实值到文档：

- PostgreSQL：应用运行、迁移、只读运维和备份使用不同账号。
- Redis 与 RabbitMQ：按应用/运维职责分离账号、Virtual Host 或等价权限。
- Keycloak：各客户端 Secret、管理/bootstrap 凭据和加密材料分离。
- BFF/会话：Cookie 签名、会话数据加密和服务端句柄摘要密钥分离，并支持版本化轮换。
- COS：上传/下载签名、清理、备份写入等按最小权限使用不同子账号或策略。
- Sentry/云监控：运行时 DSN、Source Map 上传 Token、告警 Webhook 和管理凭据分离。
- TLS、备份加密和未来 Provider Adapter：按域名、环境、供应商和用途独立。

每个 Secret 必须有非敏感清单元数据：稳定名称、用途、环境、Owner、消费者、引用路径、来源、轮换方式、影响和应急动作。清单只记录引用和元数据，不记录值、摘要片段或可用于猜测的提示。

### 4. 生成、分发和变更

- Secret 在受控管理终端或目标主机使用密码学安全随机源/官方工具生成；不得人工编写可猜密码。
- 分发只通过已验证主机指纹的受控 SSH/SFTP、私网或批准的运维入口，不通过聊天、邮件、云文档、剪贴板同步或工单附件。
- 临时文件使用限制权限并原子替换目标文件；操作完成后清理临时副本，避免 Shell 历史和终端回显。
- 两台服务器分别分发，只将该主机运行服务需要的 Secret 放到该主机。
- Secret 变更必须关联受控变更记录，但记录中只能出现 Secret 名称、版本、原因、操作人、时间和结果。
- 自动化部署账号只能读取其负责分发的引用或密文，不获得所有生产 Secret 的永久交互权限。

### 5. 轮换与撤销

- 每类 Secret 在接入时定义正常轮换、到期前轮换、人员离开、权限变化和疑似泄露轮换步骤；具体周期不在没有 Owner 时虚构。
- 支持双版本的组件先部署新旧兼容读取，再切换写入/签发，确认稳定后撤销旧值。
- 不支持双版本的组件需要维护窗口、依赖顺序、回滚条件和最大中断说明。
- BFF/会话密钥使用版本标识与有限旧密钥读取窗口；是否强制全部会话失效由事件风险决定。
- 数据库、RabbitMQ、Redis 和 COS 优先创建新凭据、切换消费者、验证后删除旧凭据，不原地共享修改万能账号。
- Source Map Token、CI 凭据和临时运维凭据使用完成后立即撤销或缩短有效期。
- 疑似泄露时先停止扩散、限制访问并轮换受影响 Secret，再处理下游会话、Token、证书和供应商凭据；不得在事故报告中粘贴泄露值。

### 6. 备份和灾难恢复

- 日常文件、数据库和配置备份默认不包含明文 Secret 根目录。
- 灾难恢复所需的最小 Secret 集合可以形成独立应急包，使用 `age` 离线公钥在上传前加密，再保存到权限独立的受限 COS 位置。
- 解密私钥不得位于两台生产服务器、普通运维电脑、Git、COS 或同一备份包中；保管人和取用流程必须单独批准。
- 应急包更新、下载和恢复都需要双人复核或等价控制，并记录审计；具体人员等待 Owner 确认。
- 恢复演练在隔离环境验证 Secret 引用、权限和启动顺序，不把生产明文复制到日常测试环境。
- 能够安全重新签发或轮换的凭据优先重建，不为了方便长期备份所有历史 Secret。

### 7. 两台主机最低安全基线

- SSH 禁止密码登录和远程 root 直登，使用个人密钥、最小 sudo 和受限来源；共享账号不得作为日常入口。
- 安全组只开放批准的公网入口；PostgreSQL、Redis、RabbitMQ、Keycloak 管理端、Flowable 管理端、ClamAV 和 Docker API 不开放公网。
- Docker Socket 不挂载进业务容器，容器不使用不必要的特权模式、Host Network、Host PID 或 root 用户。
- 系统、Docker 和第三方镜像固定版本并按风险窗口更新；安全更新先在预发布验证，紧急漏洞走加急变更。
- 启用系统时间同步、登录/sudo/关键 Secret 文件变更审计、磁盘和认证失败告警。
- 主机磁盘、COS Bucket 和备份启用腾讯云可用的静态加密能力；传输使用 TLS/SSH，跨主机明文管理协议需单独评审。
- 服务使用独立数据库角色、网络和文件权限；一个容器失陷不应自动取得其他服务 Secret。
- 离职、外包结束或设备丢失时回收 SSH、公钥、云账号、Sentry、COS、备份和部署权限，并评估相关 Secret 轮换。

### 8. 数据安全边界

- PostgreSQL、Keycloak 和 Flowable 使用独立逻辑数据库与角色；模块不得跨 Schema/数据库直接读取。
- 生产数据库和备份不复制到开发人员电脑；测试使用合成或经批准脱敏的数据。
- 文件中心继续使用私有 COS、短期预签名和服务端授权；COS Secret 不下发客户端。
- 日志、Sentry、Trace、死信和备份不得成为绕过字段权限查看客户信息的通道。
- 字段级加密、脱敏展示、导出审批、留存与删除需要根据正式数据分类和业务字段另立规则，本 ADR 不提前创建字段。

## 授权与审计

- 只有批准的部署/安全运维人员可以创建、分发、轮换、恢复或销毁生产 Secret。
- 变更记录保存 Secret 名称、环境、版本、原因、操作人、复核人、目标主机、结果和 Trace/工单引用，不保存值。
- SSH 登录、sudo、文件所有权/模式变化、Secret 文件创建替换删除、备份应急包操作和云权限变化都需要可审计。
- 文件式方案通常无法可靠审计每次进程读取，这是明确接受的限制；通过主机权限、专用容器挂载和变更审计补偿。
- 查看日志、Sentry、备份或数据库不自动授予读取 Secret 文件的权限。

## 测试与验收

- 仓库检查拒绝 `.env`、运行时 Secret 目录、私钥、已知凭据格式和高熵疑似 Secret；测试 Fixture 使用明确无效值。
- 配置单元测试覆盖 Secret 缺失、空值、错误权限、错误格式、读取失败和错误信息不泄露内容。
- Compose 检查确认生产文件只有 Secret 引用，不含明文、默认密码或敏感命令行参数。
- 集成测试验证容器只能读取自己的 Secret、挂载只读、非 root 运行和轮换后的重启/重载行为。
- 安全演练覆盖主机失陷、部署账号泄露、COS 凭据泄露、Cookie 密钥轮换和离职权限回收。
- 灾难恢复演练验证离线加密应急包能够恢复，但演练输出和日志不保留明文。

## 已考虑的方案

### 腾讯云 Secrets Manager

提供集中存储、权限、审计和轮换能力，但增加服务依赖与成本；项目负责人选择调整后的原方案，因此不采用。

### 自托管 HashiCorp Vault

能力完整，但两台服务器难以形成稳健高可用，且需要初始化、解封、存储、备份和升级运维，第一阶段不采用。

### 普通生产 `.env`

最简单，但容易被 Compose、备份、进程环境、支持脚本和人工操作扩散，权限粒度也过粗，因此不作为标准方案。

### 受限文件 + Compose Secret + `*_FILE`

符合两台服务器和低组件数量的原方案，能够避免多数明文配置扩散，同时代价和行为显式，因此采用。

## 影响与已接受风险

- 团队需要人工维护两台服务器的 Secret 一致性、轮换顺序、应急包和权限回收。
- 文件式方案缺少集中读取审计、动态租约和自动撤销，主机 root 失陷会暴露该主机上的 Secret。
- 轮换自动化程度低，若 Secret 数量或供应商数量增长，人工错误概率会明显上升。
- 使用统一 `*_FILE` 和 Secret 引用边界，使未来迁移到 Vault 或云 Secret 服务时无需修改领域模块。

## 升级触发条件

满足任一条件时重新评审集中 Secret 管理：

- Secret、服务器、环境、供应商或运维人员数量使人工分发和轮换频繁出错。
- 合规或客户合同要求逐次访问审计、硬件密钥、自动租约或集中即时撤销。
- 多次出现 Secret 不一致、过期、忘记轮换或主机文件泄露。
- 需要自动扩容、短生命周期工作负载或多可用区部署。
- 人工运维成本和风险接近或超过 Vault/托管服务成本。

## 待后续确认

- 正式 Secret 清单、Owner、轮换周期和应急联系人。
- SSH/堡垒入口、主机管理员、sudo 与双人复核流程。
- 最终 Secret 根路径、容器用户、第三方镜像 `*_FILE` 兼容矩阵。
- `age` 密钥保管人、应急包范围、COS 位置和恢复频率。
- TLS 证书签发、续期和私钥轮换方式。
- 数据分类、字段加密、脱敏、导出和保留规则。

## 非目标

- 本 ADR 不创建任何真实 Secret、账号、证书、生产路径文件或默认密码。
- 本 ADR 不授权开发人员直接访问生产主机、数据库或 Secret。
- 本 ADR 不定义 CRM 敏感字段或允许生产数据进入测试环境。
- 本 ADR 不承诺文件式方案具备集中 Secret 产品的全部能力。
