# ADR-0002：Node 24 运行时基线

- 状态：已接受
- 日期：2026-07-22
- 决策人：项目负责人
- 适用范围：整个 monorepo

## 背景

历史材料使用 Node 22，当前仓库已经通过 `.node-version` 固定 Node 24.15.0，并在根 `package.json` 中要求 `>=24 <25`。

当前前端和后端技术基线均支持 Node 24。继续使用 Node 24 可以避免因历史材料降级，并让所有本地、CI、构建和运行环境使用同一个主版本。

## 决策

1. 项目统一采用 Node 24。
2. 根 `package.json` 继续使用 `engines.node: ">=24 <25"`，防止不同主版本造成构建和依赖行为漂移。
3. `.node-version` 保存团队当前验证过的具体版本；补丁和次要版本可以在通过 `pnpm check`、构建及集成测试后升级。
4. 本地开发、CI、容器构建、迁移工具和生产运行环境必须使用 Node 24。
5. Node 主版本升级必须单独评估依赖兼容性、构建产物和运行行为，并通过新的 ADR 记录。

## 已考虑的方案

### Node 22

满足大部分当前工具的最低要求，但生命周期和后续升级空间短于 Node 24。历史材料采用该版本不是继续降级的充分理由，因此不采用。

### 不固定 Node 主版本

会导致 AI、本地开发、CI 和容器环境使用不同运行时，增加难以复现的依赖和构建问题，因此不采用。

## 影响

- 所有新建包和部署配置必须与 Node 24 兼容。
- 引入依赖前需要检查其 Node 24 支持情况。
- 当前 `.node-version` 与 `package.json` 已符合本 ADR，无需立即修改运行时文件。

## 非目标

- 本 ADR 不决定 pnpm 或 Turborepo 的版本策略。
- 本 ADR 不决定后端框架、ORM、数据库或部署拓扑。
