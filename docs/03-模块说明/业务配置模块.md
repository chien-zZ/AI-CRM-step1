# 业务配置模块

- 模块位置：`packages/platform-modules/business-configuration`
- 类型：业务中立平台模块
- 状态：边界已确认，契约和实现待评审
- 架构依据：ADR-0007、ADR-0010、ADR-0011、ADR-0013

## 开源与自研边界

- 字典与业务参数控制面：项目自研。
- 持久化、校验、缓存和传播：复用开源 PostgreSQL、Drizzle、Ajv、Redis 与 RabbitMQ。
- 不使用 Apollo、Nacos 作为业务配置事实源，也不自研数据库、缓存或消息系统。

## 职责

- 管理稳定字典类型、字典项代码及其版本化展示信息。
- 管理强类型参数定义、允许范围、值版本和生效区间。
- 管理草稿、发布、生效、停用、历史读取和重新激活。
- 提供解析结果及所用定义版本、值版本、范围和生效记录。
- 发布配置变更事件，驱动 Redis 和进程内缓存幂等失效。
- 提供差异、影响预览、权限、审计和对账能力。

## 非职责

- 不保存环境变量、服务地址或秘密。
- 不保存任意 JavaScript、SQL、模板脚本或可执行表达式。
- 不定义领域状态机、金额算法、权限策略、审批路线或数据库字段。
- 不允许一个全局配置管理员绕过各命名空间 Owner 的发布权限。
- 不把 Redis 或 RabbitMQ 当成配置事实源。

## 数据所有权

- 字典/参数定义、稳定键、Owner、类型和验证 Schema。
- 草稿与不可变发布版本。
- 作用范围声明、生效区间和生效记录。
- 发布差异、变更原因、审计引用和消费对账状态。

领域模块拥有配置语义和使用结果。需要复现的领域事实保存解析版本或必要快照，不通过“当前配置”反推历史。

## 公开能力方向

- 注册受控字典或参数定义。
- 创建、校验、发布和安排版本生效。
- 按明确上下文解析字典或参数，并返回完整版本信息。
- 查询指定时间点或版本的历史配置。
- 停用字典项、终止生效记录或重新激活历史内容。
- 查询变更差异、引用影响和缓存传播状态。

## 核心不变量

- 已发布版本不可原地修改。
- 已使用字典代码不能改成其他语义或物理删除。
- 参数值必须通过注册类型和 Schema 校验。
- 作用范围与覆盖优先级必须显式，不能依赖隐式“最后写入者”。
- 关键业务操作无法解析所需配置时失败关闭。
- 定时消息只是唤醒手段，PostgreSQL 有效区间才决定配置是否生效。

## 待确认

- 字典、参数、发布、生效和解析的具体契约。
- 第一阶段允许的参数类型、范围和覆盖优先级。
- 发布风险分级、Flowable 审批触发条件和管理界面。
- 缓存、定时生效、回滚、引用分析和对账策略。
