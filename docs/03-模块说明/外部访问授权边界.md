# 外部访问授权边界

- 状态：能力边界已确认，首个业务场景、契约、模块位置和实现待确认
- 架构依据：ADR-0007、ADR-0015、ADR-0017、ADR-0019

## 职责

- 区分匿名、邀请授权和 Keycloak 长期登录三种外部访问模式。
- 对业务模块批准的邀请请求提供不透明 Token、摘要校验、有效期、次数、撤销、原子消费和技术审计能力。
- 向授权层提供经过验证、最小化且不冒充身份的访问模式/能力上下文。
- 统一外部访问的默认拒绝、防枚举、限流接入和稳定错误语义。

## 非职责

- 不定义外部主体，不拥有客户、合作方或其他业务档案。
- 不决定某个资源能否被邀请访问，也不拥有资源当前状态。
- 不把邀请凭据视为身份或创建 Keycloak 用户。
- 不拥有验证码、WAF 或风控供应商，也不替代业务幂等和数据校验。

## 所有权边界

- 业务模块拥有资源、邀请资格、允许动作和业务结果。
- 外部访问授权薄层拥有邀请凭据安全状态，但只在首个真实场景确认后创建正式模块和 Schema。
- Keycloak 拥有长期认证主体与会话上游事实。
- Redis 只用于短期速率/风险协调；邀请授权耐久事实必须位于 PostgreSQL。

## 公开能力方向

- 申请、撤销和核验用途受限的邀请授权。
- 原子预留/消费和幂等结果关联。
- 构造匿名、邀请或登录三选一的访问上下文。
- 查询不包含明文 Token 的邀请管理与审计状态。

具体操作、字段、状态、错误码和包位置必须由首个业务场景先在契约中确认。在此之前不创建占位 API、数据表或空平台包。

## 失败模式

- Token 无效、过期、撤销、超次、受众错误或风险冻结。
- 匿名请求调用未公开操作，或邀请调用未授权资源/动作。
- 邀请有效但业务资源状态已不允许操作。
- 消费与业务写入部分失败、并发超用或重复提交。
- Redis、验证码或边缘防护不可用。

这些情况默认拒绝，并按外部错误最小披露规则返回稳定结果；不能降级到另一种访问模式继续操作。

## 待确认

- 首个外部业务资源和 Owner。
- 平台薄层的最终包位置、公开契约和数据库模型。
- 邀请生命周期、附加验证、隐私和风控策略。
