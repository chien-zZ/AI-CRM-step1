# 表单定义模块

- 模块位置：`packages/platform-modules/form-schema`
- PC Web 渲染入口：`apps/workbench-web`
- 类型：业务中立平台模块
- 状态：边界已确认，方言、契约和实现待评审
- 架构依据：ADR-0001、ADR-0009、ADR-0013

## 开源与自研边界

- 数据结构和校验协议：开放标准 JSON Schema 2020-12。
- 校验引擎：开源 Ajv，服务端严格校验为权威。
- 定义注册、版本、发布、UI Schema 和项目错误映射：自研。
- PC Web 渲染器：基于 Ant Design Form/ProComponents 自研轻量白名单渲染器。
- 第一阶段不引入 Formily、拖拽设计器或完整低代码平台。

## 职责

- 管理表单身份、Owner、草稿和不可变发布版本。
- 校验受控 JSON Schema 方言和 UI Schema。
- 管理允许的格式、自定义关键字与 UI 组件注册信息。
- 提供稳定、版本化的 `FormDefinitionReference`。
- 为领域模块、Workflow 和前端提供按准确版本读取及校验能力。

## 非职责

- 不拥有任何具体业务表单的语义或用户提交数据。
- 不执行授权、领域状态迁移、金额计算或审批路由。
- 不允许任意脚本、SQL、HTML、远程组件或远程 `$ref`。
- 不保证任意复杂业务页面都能由 Schema 生成。
- 不把 Flowable 变量当成表单定义或提交数据仓库。

## 数据所有权

- 表单稳定身份、Owner 和命名空间。
- 草稿内容、发布制品、单调版本和内容摘要。
- JSON Schema、UI Schema、兼容和发布元数据。
- 组件、格式及扩展关键字注册信息。

具体业务模块拥有表单含义、提交记录和领域校验。发布制品由表单模块保存供运行时稳定解析，但不改变语义所有权。

## 公开能力方向

- 创建和修改草稿。
- 校验并发布不可变版本。
- 按定义 ID 和版本读取或验证表单数据。
- 获取前端允许使用的 UI Schema 和组件注册信息。
- 停止新流程使用某版本，同时保持历史版本可解析。
- 查询版本差异、引用和兼容信息。

## 核心不变量

- 发布版本不可原地修改。
- 服务端必须使用调用方声明或事实记录绑定的准确版本校验。
- 前端隐藏、禁用和校验不能替代服务端授权和领域规则。
- 未知关键字、格式、组件和版本必须明确失败。
- 历史流程与数据不能因发布新版本改变解释。

## 待确认

- JSON Schema 受控方言、UI Schema 和错误契约。
- 首批字段组件、格式、联动范围及无障碍要求。
- 版本兼容规则、发布权限和管理界面范围。
- Workflow 和领域模块保存引用或快照的具体条件。
