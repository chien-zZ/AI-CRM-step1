# 认证上下文与会话边界

- 状态：架构边界已确认，接口与实现待开发任务
- 架构依据：ADR-0004、ADR-0005、ADR-0006、ADR-0017、ADR-0018

## 职责

- Keycloak 负责凭证、登录、MFA、联合身份、认证会话和 Token。
- `apps/api` 的 BFF 适配层负责各客户端 OIDC/提供商登录编排、服务端会话、Cookie/小程序句柄、刷新、轮换和注销。
- `auth-context` 验证可信 Keycloak 结果并生成与传输无关的内部主体上下文。
- `authorization` 根据主体、客户端、动作、资源和数据范围作最终业务授权。

## 非职责

- 不管理人员、组织、岗位或任职。
- 不定义外部主体、自动注册和外部账号恢复业务规则；内部人员主体关联由 `organization` 按 ADR-0018 管理，匿名/邀请访问不是认证会话并执行 ADR-0019。
- 不签发自有认证 JWT，不在客户端保存 Keycloak Token。
- 不以登录成功替代业务授权，不读取领域表补全身份。

## 数据所有权

- Keycloak 拥有认证用户、凭证、联合身份和认证事件。
- Redis 只保存有 TTL 的应用会话、一次性认证状态和短期协调数据。
- 内部人员主体关联由 `organization` 持有；邀请访问的耐久授权事实由后续确认的业务中立薄层持有；外部账号生命周期仍待确认。永久事实不能存入 Redis 或客户端。
- 客户端只持有对应传输允许的不透明会话标识，不拥有身份事实。

## 公开边界

- 登录、回调、当前会话、CSRF、注销和会话失效通过按客户端受众拆分的 HTTP 契约公开。
- 微信小程序 `wx.login` code 只进入外部小程序认证端点，不能复用于 H5 或内部客户端。
- 下游模块只接收标准主体上下文，不接触 Cookie、会话句柄、Keycloak Token 或提供商标识。
- 内部主体上下文必须解析到唯一 Workforce Person 和有效 Employment；单个 Assignment 失效只移除对应上下文。
- 具体端点、字段和错误码必须先进入按模块维护的 OpenAPI 源，再实现代码。

## 失败与安全

- Keycloak、Redis、提供商验证、Token 刷新或会话解密失败时失败关闭。
- 客户端/受众不匹配、CSRF、重放、过期、撤销或关联冲突均拒绝访问并记录安全审计。
- 重复回调和重复登录请求不能产生多个意外有效会话或重复关联。
- 日志、指标和 Trace 不记录 Token、Cookie、会话凭据、授权码、`session_key` 或 Secret。
