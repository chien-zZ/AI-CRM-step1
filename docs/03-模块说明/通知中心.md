# 通知中心

- 模块位置：`packages/platform-modules/notifications`
- 异步运行入口：`apps/worker`
- PC Web 入口：`apps/workbench-web`
- 类型：业务中立平台模块
- 状态：边界与第一阶段范围已确认，契约和实现待评审
- 架构依据：ADR-0006、ADR-0007、ADR-0009、ADR-0010、ADR-0014、ADR-0020

## 自研与开源边界

- 通知意图、站内通知、模板版本、偏好和渠道投递控制面：项目自研。
- 模板变量替换：使用受限开源 Mustache，不允许脚本或任意 Helper。
- 持久化、消息和缓存：复用 PostgreSQL、RabbitMQ 和 Redis。
- 外部渠道：未来由通知中心定义供应商中立 `ChannelAdapter` Port，具体 Adapter 可复用 `integration-runtime` 并在 Worker 组合；第一阶段不实现。
- 第一阶段不引入 Novu 或完整通知编排平台。

## 职责

- 接收和幂等处理显式通知意图。
- 解析稳定收件范围并保存实际收件人快照。
- 管理受控模板、变量 Schema 和不可变发布版本。
- 生成站内通知，管理列表、未读/已读和归档状态。
- 管理用户偏好、免打扰和强制类别裁决。
- 调度并记录渠道投递、回执、重试、死信和人工重放。
- 管理安全深链、审计、指标和对账。

## 非职责

- 不决定业务为何需要通知，也不查询业务表猜测触发条件。
- 不拥有 Task、审批、SLA、业务状态或预警处置结果。
- 不把服务商受理/送达当成用户已读或工作完成。
- 不直接读取组织、Keycloak、Workflow 或领域数据库。
- 不允许业务模块直接调用外部渠道。
- 不在第一阶段实现企微、微信、短信、邮件、JPush、WebSocket 或 SSE。
- 不因 `integration-runtime` 已存在就视为任何外部通知渠道已获批准。

## 数据所有权

- 通知意图、幂等键和来源引用。
- 通知、实际收件人、渲染快照和站内用户状态。
- 模板身份、变量 Schema、草稿和不可变版本。
- 偏好、免打扰、强制类型裁决和所用版本。
- 渠道地址、投递计划、尝试、回执、失败和重放记录。

通知保存资源引用和必要展示快照，不拥有来源业务对象。渠道地址不是认证主体或组织事实。

## 公开能力方向

- 通过 `platform-sdk` 提交带幂等键的通知意图。
- 查询当前主体的通知列表、详情和未读数。
- 幂等标记单条/受控批量已读或归档。
- 查询和修改当前主体允许的通知偏好。
- 注册、校验和发布通知模板版本。
- 由授权运营人员查询失败并执行受控重试或重放。

## 核心不变量

- 重复意图不能产生重复通知或重复渠道副作用。
- 收件人使用稳定引用，并保存生成时的实际解析结果。
- 历史通知内容不随模板新版本改变。
- 用户已读只能由受权用户的站内操作产生。
- 通知深链每次访问重新授权，不能携带秘密或敏感数据。
- 外部渠道失败不删除站内事实，也不改变业务状态。
- 需要处理结果的工作必须有独立 Task 或业务流程。

## 失败模式

- 收件人为空、歧义、超过限制或组织服务不可用。
- 模板版本不存在、变量不合法或渲染失败。
- PostgreSQL 已生成通知但 RabbitMQ 投递延迟。
- 偏好在计划和实际投递之间变化。
- 渠道限流、超时、拒绝、回执重复或死信。
- 深链目标权限撤销或资源不存在。

所有失败保留明确状态、幂等、审计和恢复路径。不得回退为广播、公开链接或绕过偏好/授权。

## 第一阶段范围

- 站内通知、列表、详情、未读数和已读/归档。
- TanStack Query 轮询，不使用长连接。
- Mustache 纯文本模板与变量 Schema。
- 最小偏好、幂等、审计和 Worker 失败恢复。
- 业务中立 walking skeleton，不含具体 CRM 通知类型。
